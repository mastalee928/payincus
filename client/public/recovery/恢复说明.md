# PayIncus 中文恢复说明

每个新备份集目录同时保存 `payload.enc`、`complete.json` 和 `payincus-backup-YYYYMMDD-HHMMSS-UTC.zip`。ZIP 是额外副本，密码与同次自动恢复备份相同。UTC 比北京时间早 8 小时，例如 20261021-020000-UTC 为北京时间 10 月 21 日 10:00。

ZIP 使用 AES-256 密码保护，可用支持 AES ZIP/ZIP64 的 7-Zip 或 WinRAR 打开；Windows 自带解压器可能不支持。ZIP 中的文件名可见，文件内容需要密码。请另存备份密码、OSS 凭据、备份集目录、面板版本和 PostgreSQL 大版本。

包内包括整库 `database.dump`、整库文本 `database.sql`、按表名排列的 `tables/<schema>/<table>.sql`、角色及授权资料 `database-globals.sql`、逐表/序列/大对象校验报告、运行配置、受管证书与本机网关身份资料，以及本说明和交互工具。特殊表名中的字符会百分号编码。全部 SQL 均从同一个已验证整库归档生成。正式恢复以整库为单位，避免余额、订单、流水之间失去关联。

## 面板还能打开

1. 打开「阿里云 OSS → 备份与恢复」，找到故障前的成功备份。恢复仍读取 `payload.enc`，不必上传或导入额外 ZIP。
2. 点击「恢复预检」，输入该备份的原密码。等待任务显示「预检可用」；系统会下载、认证并在临时库还原与核对，新备份还会逐表核对数据、序列和大对象。
3. 先隔离旧主控并保存目标机当前数据库、配置和证书。在维护窗口输入页面显示的 `RESTORE <预检任务 ID>`，执行恢复。
4. 恢复后保持业务保护。恢复的会话及 API 凭证会失效，需重新登录。核对真实宿主、实例、库存、支付、备份后新增账目及待处理任务，重新授权需要使用的 API 凭证。
5. 如需撤销，选择「回退到恢复前」。核对完成后选择「核对完成，恢复运营」。未核对时不要解除保护。

## 服务器损坏、面板打不开

1. 在云厂商侧隔离旧主控，避免两个主控同时控制宿主。保留旧磁盘和日志。
2. 在新的 Linux 主控安装**与备份相同或同一主版本内较新的稳定面板版本，以及相同 PostgreSQL 大版本**，配置新主控的数据库、网站域名及直连管理网关。目标版本须包含自动兼容恢复功能；旧执行器仍要求版本和迁移指纹一致。网关在主控 root 终端执行 `sudo bash install-panel.sh --configure-host-pool` 配置，后台「机器池 → 配置管理网关」提供步骤。
3. 登录新面板，保存 OSS 凭据。在「查询备份目录」输入原安装的目录（根目录 + 原 installationId/），查找旧备份，再按上面的预检、恢复、核对流程操作。
4. 如果后台不能登录，但已安装的数据库和恢复执行器仍可用，可下载 `payincus-recovery.py` 和本说明，在目标机执行 `sudo python3 payincus-recovery.py configure`。工具会交互询问 OSS 凭据，保持定时备份关闭，密码不写入命令参数。
5. 依次执行 `sudo python3 payincus-recovery.py preview`、`sudo python3 payincus-recovery.py status`。预检成功后执行 `restore`，输入成功预检任务 ID 和确认串。每次提交后使用 `status` 查看结果。必要时使用 `rollback`；完成核对后使用 `resume`。工具调用目标机已安装并封存的程序，不下载或执行备份中的脚本。

上述流程只需要可用的新主控、OSS 访问权限、原备份目录及原密码，不依赖旧服务器在线。恢复整个平台数据库、应用数据解密密钥、受管证书、机器池和网关身份；保留新服务器的数据库连接、域名、运行配置、JWT 身份及公网管理地址。旧备份会先认证、隔离恢复并核对完整性，再按当前发行包的受信迁移升级，匹配目标结构才允许恢复。已知的同一 SQL 的 LF/CRLF 换行差异不会阻断换机；未知迁移、较新备份、跨应用主版本或 PostgreSQL 大版本、迁移升级失败及结构不匹配会明确拒绝。预检后目标变化须重新预检。

隔离恢复会沿用备份的数据库编码和 libc locale。若新系统提示缺少原 locale（例如 `en_US.UTF-8`），请安装对应系统 locale 后重新预检，不要替换排序规则或跳过完整性校验。

换公网 IP 后，旧宿主还必须能到达新网关。优先使用可直连的稳定管理域名，切换其 DNS 到新主控；若宿主配置的是旧 IP，则需通过宿主控制通道更新 WireGuard 端点。Cloudflare 网站 Tunnel 不转发管理 UDP。主控数据恢复成功不等于离线宿主已重连；核对现存实例后再解除库存隔离。

## 额外 ZIP 的用途与边界

额外 ZIP 便于自行下载、解压浏览逐表 SQL，并保留完整 SQL 与原生整库归档。可交给数据库维护者在**隔离的新数据库**使用 `pg_restore` 或 `psql` 检查；不要把逐表 SQL 零散导入正在运营的数据库，也不要直接执行 globals 或覆盖 `.env`、网关密钥。权限、连接地址和宿主身份需要按目标机审查和映射。面板预检/恢复流程会统一完成数据库切换、受管文件恢复、会话撤销和恢复保护。

旧格式备份仍可读取，但不会补生成额外 ZIP；旧备份没有新的完整性报告时，不能等同于通过新的逐表完整性校验。新备份只在整库实际恢复验证、ZIP 逐项解密校验和两份对象 OSS 回读都成功后才发布 complete 标记，然后执行保留清理。清理失败会显示警告。

这是备份快照时刻的数据；两次备份之间新增的交易不在旧快照内，当前不提供持续 WAL 归档。VPS 磁盘、客户网站文件、外部项目数据库与自定义非受管文件需单独备份。
