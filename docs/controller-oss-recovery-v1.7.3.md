# v1.7.3 单机主控兼网关的 OSS 恢复流程

首要场景是 A 同时担任主控和网关、A 整机完全失联，在 B 全新安装 PayIncus 并从 OSS 恢复后，原宿主自动连接 B，客户实例、磁盘和网络保持正常。此页说明操作流程，不代表整机失联验收已完成；owner 在上线后执行真实测试，DD 也由 owner 执行。

## 在 A 完成准备

1. 升级后打开「机器池 → 管理网关」，点击本机检查，查看系统生成的计划并确认配置。本机不填写SSH地址或密码；端口和至少 `/20` 的地址池自动处理，保留原管理地址、密钥和 peer。
2. 固定直连网关域名只保存一次。保存后系统自动为已接入宿主补装地址更新，新宿主也会自动加入。检查逐台步骤与结果；失败项会保留具体原因，支持批量重试。只有全部需恢复的宿主准备完成，才进入最终备份。
3. 在「系统 → 阿里云 OSS」完成配置测试和完整备份，确认上传、完整性与回读均成功。把备份集、独立密码、访问凭据和管理员/MFA恢复材料安全保存到 A 之外。
4. 保存备份截止时间，以及后续支付、充值、每笔续费、退款、订单、交付、余额和权限变动的外部凭证。客户磁盘不在面板数据库备份中，不覆盖或重建客户实例。

## 在 B 恢复

1. 在 B 全新安装相应正式发行包；完成用户端、管理端的网站入口。
2. 使用新后台「机器池 → 管理网关」，直接检查B本机并确认计划，让恢复所需的网关基础目录和服务就绪，不通过SSH连接本机。
3. 在 OSS 页面选择 A 的最终成功完整备份，输入原独立密码，执行预检与正式恢复。恢复 A 的整库及原控制/WireGuard/管理 SSH/Incus身份，保留恢复保护，不重新生成原宿主身份或重绑每台宿主。
4. 固定网关域名的 A 记录指向 B，保持原传输端口和正常云网络放行。已准备的宿主周期重解析原域名，更新原 peer 的 Endpoint；无需管理员逐台 SSH 或填写管理地址/端口。
5. 在恢复保护内检查实际握手、原SSH/Incus信任、Agent心跳和客户实例清单，逐项核对较新账目、到期、库存与任务。存在差异时保留保护；不能仅凭DNS保存或旧快照在线便认定恢复成功。
6. 核对完成后解除保护，验证正常购买/交付、公钥初始化、NAT SSH、续费账单、自动补续、原TG通知、自然五分钟巡检和到期处理。删除只在确认远端实例不存在后释放库存。

后端始终只运行一个实例，A 的退出回执不是 B 恢复的前提。A 复活隔离、独立主备切换/切回、四拓扑、唯一写者及72小时验收仍按完整 P0–P6工程继续，不能从本页或发行成功推断已全部完成。
