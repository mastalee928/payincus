# 主机接入与管理

管理端入口是「主机接入与管理 → 机器池 / 定价」。用户端通过 `/purchase` 选择地区、完整配置、镜像和数量，加入 `/checkout` 购物车后统一付款。页面沿用 PayIncus 的布局、主题和账户余额。

地区国旗在「机器池 → 管理分组 → 编辑地区 → 国家 / 地区」设置。选择国家并保存后，购买页的地区列表、当前选择、定价表及新加入购物车的配置会显示对应国旗；只填写地区名称不会自动设置国家。

## 机器池

- 按机型、地区、资源预设、客户磁盘配额组织机器；已有 PayIncus 主机也可在机器池中补设分组与规格。
- E2、ARM1C 至 ARM4C 的 CPU / 内存预设沿用接入资源计算；磁盘可独立定价。分配前校验真实容量、存储池、镜像兼容性和 Agent 状态。
- 一个专用主机只能分配一个客户实例。正在创建、错误实例、待完成清理或迁移预占都会阻止再次出售。
- 机器行直接提供「SSH」和「删除」。SSH 显示连接信息并复制命令；手工接入且未保存 SSH 信息的主机需要填写地址、端口、用户名。
- 自动接入的机器通过管理网关连接：先复制网关登录命令，再在网关执行带管理密钥的 SSH 命令。面板不提供浏览器终端，不返回管理私钥。
- 删除会移除池内机器记录；已分配实例或有运行任务时返回冲突。不会自动卸载远端 Incus、擦除磁盘或移除网关 peer。

## 定价与结算

一个商品由「机型分组 + 资源预设 + 地区分组 + 磁盘」确定。定价矩阵可一次保存多项变更，包含删除；任一变更失败则整批回滚。支持零元配置。月费、一次性开通费按分保存。

购物车不占库存。结算事务重新检查售价、实例名称、镜像与 SSH 密钥归属，锁定余额及机器后整单扣款、分配。缺货时整单回滚；请求 UUID 确保网络重试不会重复扣款。已接受订单通过订单 UUID 恢复进度，连接信息只展示实际分配的公网 SSH 端口。

每台实例有独立账单。开通失败沿用 PayIncus 的退款流程，退回该台月费和一次性费用；续费只收月费。删除定价会停止新售卖，同时保留历史计费方案关联。底层隐藏套餐不进入普通套餐购买入口。

独占交付使用 Incus 的整地址 forward，将宿主机公网 IPv4 的全部端口交给唯一客户实例，SSH 固定为公网 IP 的 22 端口。管理端可选择 TCP 或 TCP+UDP；Agent 确认规则已应用、并用保存的客户密码通过公网 SSH 登录后，成功页才显示可连接地址。客户不需要自行配置端口转发。宿主机的 SSH 和 Incus 管理使用 WireGuard 管理地址。

用户端只显示公网 IPv4 和实际分配的公网 IPv6，没有 IPv6 时显示「未分配」。隐藏宿主机内部名称、虚拟化实现、带宽和端口映射配额；流量为 `unlimit / 无限制`，不显示百分比。宿主机名称仍保留在管理端。独占实例默认不设月流量上限，带宽配置上限为 100000Mbit，实际速度取决于宿主机和云厂商。

已有实例、订单、用户与余额的数据迁移属于单独的上线操作，本地代码变更不会搬迁 ociee 数据。

## 故障换机

管理员在机器池的已分配机器上选择「故障换机」，选择同地区、机型和架构、容量足够的空闲机器。可以使用该实例已完成上传的异地备份恢复；没有备份时必须明确确认重建系统，原磁盘数据不会凭空恢复。

任务先预占备用机器并隔离旧机，随后创建系统、配置整地址转发并验证公网 SSH。通过后切换原实例的机器绑定，保留用户、实例名称、价格、到期时间和续费设置。新 IP 出现在用户实例页，旧机保持隔离，不能重新出售。

失败时，只有确认目标实例和网络配置已清理，才能释放备用机；清理失败或进程中断会继续隔离，避免误售。旧机再次可访问后，机器池显示“管理连接在线”和“已隔离，暂停出售”，两者分别表示连接和销售状态。实例数量是平台绑定数量，不代表旧机磁盘已清空。

机器行的“检查与恢复”会检查管理连接、Agent、协议、任务、真实实例、数据卷及转发规则。只允许清理已确认属于历史换机、已经停止且没有再次分配的旧系统；同名重建系统、额外项目或数据卷、未知规则和运行中的系统均要求人工检查。管理员确认旧数据已备份或不再需要后，可选择“清理旧系统并解除隔离”。删除后再次检查远端为空，再校正占用计数、解除隔离；清理失败保持隔离，可重新检查后重试。当前新机器上的用户实例和账单不会改变。没有遗留数据时可直接解除隔离，仍需满足规格及定价条件才能出售。

## 公网协议与地址变更

在机器池选择 TCP 或 TCP+UDP 后，设置自动随 Agent 心跳下发，无需另外点击应用。页面在等待期间显示“正在自动应用”，收到宿主机确认后显示实际生效结果，默认心跳下通常需要 1–2 分钟。离线时等待重连，失败时可“重新下发”。TCP 模式阻断用户实例的公网 UDP 入站，包括此前建立的入站流；保留实例主动发起的 DNS 等 UDP 请求的返回流量，以及宿主机 WireGuard 管理通信。

机器池已接入的单租户主机默认每分钟检测公网 IPv4。候选地址来自管理网关上已注册 WireGuard peer 的认证端点，不使用 HTTP 转发请求头，也不把出口地址直接当作交付地址。主控通过固定证书验证的 Incus 管理连接读取真实网卡和实例信息，再用 SSH 密钥交换验证公网入口确实属于当前系统。验证无需用户密码，用户自行改密码不会影响同步。

运营操作：先在云厂商更换原机器的公网 IPv4，保留系统与 `incudal-mgmt` 配置。WireGuard 主动握手恢复后通常在 1–3 分钟内检测、验证并同步。也可在机器池点击“检测与同步 IP → 保存并立即检测”。机器池、节点公网字段、用户实例与开通成功页统一读取已验证地址；实例页和成功页会刷新。管理连接地址、实例数据、原价格和到期时间保持不变，接入任务中的原始地址继续作为历史记录。

内网 IPv4 同时改变时，只从真实网卡地址中选择绑定。先建立当前实例专属的新转发并验证公网路径，再清理同一实例的旧转发、提交地址；不会覆盖其他实例的规则。多网卡或多地址无法确定绑定时，在高级设置填写实际内网 IPv4。网卡、防火墙变化导致公网验证失败时保留重试状态，需先恢复正确网络配置。

公网入口和出口不同的环境可选择“手动指定”，该选择会持久保存，后续扫描继续验证指定入口。用户修改 SSH 端口时，在高级设置填写实际端口；空机使用接入时记录的宿主机 SSH 端口。SSH 关闭、用户实例关机、正在创建/换机/备份、协议未应用或管理隧道失联时显示具体原因并自动重试，不自动启动用户关机的实例。检测到地址变化但尚未验证时暂停空机出售并隐藏用户端旧连接地址；数据库触发器同时拒绝过期库存请求的分配和换机预占。成功后自动解除该 IP 等待状态，故障隔离仍由独立恢复流程处理。

管理网关新增受限 `peers` 只读命令，需要一并更新 `/usr/local/sbin/incudal-onboarding-gateway`；仅使用 IPv4 自动同步时不需更新宿主机 Agent。IPv6 自动同步的要求见下节。

## 自动接入主机的多个 IPv6

对自动接入、单租户且未设置独立 routed 前缀的节点，系统读取宿主物理网卡上实际配置的公网 IPv6。接入前已有或接入后添加、更换、删除地址，都无需重新接入。一个节点的全部 IPv6 交给同一客户实例；不会从 `/64` 路由中自行生成未经云厂商分配的地址。普通手动接入或 routed IPv6 的原有配置保持由管理员管理。

需要支持 `network_forward_snat` 的 Incus、nftables，以及报告 `dedicated-ipv6-v1` 能力的新版 Agent。管理端会提示缺少的条件。IPv6 安全组独立于 IPv4，也需允许用户所需的流量。主控需要 IPv6 出站连接，才能验证客户公网 SSH 身份。

OCI 自动接入节点使用新版 Agent 从固定的 IMDS v2 网卡接口读取实际分配地址，按 MAC 匹配物理网卡后配置 `/128` 地址与独立的默认路由。此过程使用 Linux 通用接口，兼容 Debian/systemd 与 Alpine/OpenRC，不依赖 DHCPv6 续租，也不需要重启实例。通常 Agent 在 15 秒内识别附加或更换，随后面板约每分钟完成交付检查。云平台尚未返回地址、Agent 版本过旧或协议尚未生效时，单纯等待不能代替处理对应原因。

Agent 只删除自己记录过且已被云平台撤回的地址，保留无关手工地址和路由；元数据失败或缺少地址字段时保留上一次配置。宿主重启后自动重建，新增地址在绑定前先限制宿主服务的公网访问，客户转发与管理隧道仍正常工作。其他云平台继续读取物理网卡实际地址，需通过该平台的网络配置机制使地址进入宿主系统。不能把只分配了前缀但未分配具体地址的网段当作可售 IPv6。

机器池与节点网络信息展示所有检测到的地址。后台约每分钟扫描，也可点击“立即同步 IPv6”。客户实例与开通结果只展示已完成网络配置、通过公网 SSH 身份校验的地址；失联不会被误认为全部地址被移除。关机、隔离或正在执行其他实例任务时记录变化，恢复后再应用。更新 IPv6 不改变 IPv4、实例磁盘、价格或到期时间。地址较多时分批验证，失败地址不会阻塞后面的新地址。

每个 IPv6 的 TCP/UDP 全端口均交给实例，协议限制与 IPv4 共用现有 TCP／TCP+UDP 开关；管理 SSH 继续使用 WireGuard。Agent 为每个内部地址维护对应公网出口，并允许必要的 IPv6 邻居发现。客户不能通过网桥访问宿主管理服务。规则支持宿主及实例重启恢复；宿主暂时无法联系主控时，已保存规则仍可恢复。实例内使用平台管理的内部地址，应用若同时监听多个 IPv6，应绑定相应地址或使用 `IPV6_PKTINFO` 按收包地址回复 UDP。

数据库迁移 `202610160002_dedicated_ipv6` 分别保存宿主地址清单与实例已验证的交付状态。更新面板时必须同步更新宿主 Agent；旧版稳定 Agent 不具备上述能力。

## 自动接入前提

新机器必须能通过公网 IPv4 或解析到公网 IPv4 的域名进行 root SSH 登录。表单支持逐台或 CSV 导入，使用密码或未加密私钥。可填写 SSH 主机指纹；未填写时记录首次连接的指纹，重试时严格匹配。接入凭证加密保存在任务中，成功后删除，过期后清除。

接入流程安装依赖、探测容量、保留系统资源、配置磁盘 swap、建立 WireGuard 管理连接、运行当前 PayIncus 安装脚本、创建系统存储池，并等待 Agent 心跳。它只接入空机器；已有其他 Incus/LXC 或其他接入标记时会停止，避免接管已有实例。

一键安装时会提示填写管理网关的公网 IPv4 或直连域名。填写后，脚本自动创建 WireGuard 管理接口、受限应用密钥和独立宿主管理密钥，验证后端能够通过固定 SSH 主机指纹访问网关，再写入 `.env`。管理网关地址不能经过 CDN 或 Cloudflare Tunnel；需要在云厂商安全组放行对应的入站 UDP 端口。

默认使用 `10.253.240.1/24`、WireGuard UDP `51820` 和主控 SSH `22`。可通过 `ONBOARDING_PUBLIC_HOST`、`ONBOARDING_MANAGEMENT_ADDRESS`、`ONBOARDING_WG_PORT`、`ONBOARDING_CONTROL_SSH_PORT` 配置。脚本保留已有密钥和 peer，发现网段或端口冲突会停止。主控 OpenSSH 需允许 root 公钥认证；脚本不会修改全局 root 登录策略。

安装时留空可稍后运行：

```sh
curl -fsSL https://raw.githubusercontent.com/mastalee928/payincus/main/scripts/install-panel.sh -o install-panel.sh
sudo bash install-panel.sh --configure-host-pool
```

已有独立网关或需要手动配置时，网关需具备：

1. Linux、Python 3、WireGuard 工具与 OpenSSH；已启动 `incudal-mgmt` 接口，配置文件为 `/etc/wireguard/incudal-mgmt.conf`。
2. 管理子网位于 `10.0.0.0/8`，前缀长度 `/16` 至 `/30`，避开 Incus 的 `10.10.0.0/22` 与其他现有网段。
3. 后端所在网络可访问节点的管理地址。当前接入 worker 直接通过管理地址连接节点；常见部署是后端与网关同机。
4. 公网 WireGuard UDP endpoint 可达。控制机到节点的管理 SSH 和 Incus 8443 端口可达。
5. `PUBLIC_URL`（或首个 `FRONTEND_URL`）为节点可访问的面板 HTTPS 根地址，安装与 Agent API 经现有代理可达。

在网关上执行发行包内 `scripts/install-onboarding-gateway.sh <应用密钥绝对路径>`，生成权限受限的应用密钥和独立主机管理密钥。应用密钥只允许网关状态查询与注册 peer。密钥路径应放在持久目录，后端服务用户需要读取权限。

按 `.env.example` 配置：

| 变量 | 含义 |
| --- | --- |
| `ONBOARDING_GATEWAY_HOST` / `ONBOARDING_GATEWAY_PORT` | 后端访问网关的 SSH 地址 / 端口 |
| `ONBOARDING_GATEWAY_KEY_PATH` | 后端可读取的受限应用私钥绝对路径 |
| `ONBOARDING_GATEWAY_FINGERPRINT` | 网关 SSH 主机公钥的 `SHA256:...` 指纹 |
| `ONBOARDING_WG_ENDPOINT` | 节点访问网关的 `公网域名或IPv4:UDP端口` |
| `ONBOARDING_SSH_JUMP_HOST` / `PORT` / `USER` | 机器池向运维人员显示的网关登录信息 |

配置好后重启唯一的后端进程。缺少网关配置时可继续管理已有机器和定价，自动接入会显示配置问题。发布工作流包含 worker 所需探测、swap、网络与网关脚本。

## 数据库与本地检查

迁移 `202610150001_host_pool_checkout` 增加分组、接入任务、定价和购物车订单表；`202610150002_dedicated_delivery` 增加协议状态、独占交付确认和故障换机记录，并为现有机器池实例设置无限流量与独占交付。`202610150003_host_public_ip_sync` 增加 IP 检测状态及阻止未验证地址被再次出售的触发器。数据库触发器保护专用主机占用、隔离和客户配额。先在独立 PostgreSQL 16 数据库验证，再应用到主控。

```sh
pnpm --filter server test:host-pool-guards
pnpm --filter server test:host-public-ip
pnpm --filter server test:host-public-ipv6
pnpm --filter server test:dedicated-delivery
pnpm --filter server test:instance-create-failure-compensation
pnpm --filter server test:frontend-route-guards
pnpm --filter client type-check
pnpm --filter server type-check
pnpm build
```

真实数据库集成测试只允许本机、名称以 `_pool_test` 结尾、已应用迁移的隔离数据库。运行 `DATABASE_URL=... pnpm --filter server test:host-pool-integration`。测试创建独立命名的夹具，覆盖库存竞争、重复提交、混合配置、价格变化、退款、定价删除、SSH 权限与机器删除竞争；不连接真实宿主机。

`test:host-replacement-integration` 使用同样受限的隔离数据库，验证换机权限、并发预占、失败后的价格和账期保留、清理确认与持久隔离。`test:host-public-ip-integration` 验证换公网/内网 IP、身份不匹配、失败重试、规则归属、停止/忙碌状态、手动入口、SSH 端口、重复请求和数据库分配阻断；远端网络使用模拟客户端。`python3 scripts/test-ingress-network.py` 在 Linux 网络命名空间中验证 TCP 和 UDP 实际数据包。

`test:host-public-ipv6-integration` 验证 IPv6 新增、更换、移除、任务互斥及客户数据映射。Linux 上执行 `cd agent && INCUDAL_IPV6_NETNS_TEST=1 go test ./internal/dedicatedipv6`，在独立网络命名空间验证两个 IPv6 的入站端口、独立出站 TCP/UDP/ICMP、邻居发现、管理隔离、协议切换和防火墙重载。测试地址只存在于隔离网络，不占用云侧地址。

Linux 上可执行 `python3 scripts/test-onboarding-gateway.py` 和 `python3 scripts/test-host-swap.py`。这些测试只操作临时目录和模拟系统命令。真正的安装、WireGuard、防火墙、TLS 与 Agent 心跳仍需在一台空白测试主机完成验收。

Alpine 接入使用原生 Incus 软件包、OpenRC 服务和管理隧道；Agent 安装、回滚及自更新支持 OpenRC。接入租约统一按 UTC 比较，避免数据库使用其他时区时重复领取运行中的任务。`test:host-onboarding-lease-integration` 在同样受限的本地测试数据库中验证非 UTC 会话的租约排他与过期恢复。
