# 机器池宿主 BBR 与到期停止／删除复查

本轮根据 owner 最新澄清收敛为机器池宿主 BBR，覆盖新对接和已经对接；客户实例 BBR 不属于自动设置范围。此前候选中的客户网络命名空间设置已移除，没有部署生产。到期停机与截止删除继续共同验收。发行保持暂停。

## 最终修复

| 问题 | 最终行为 |
|---|---|
| 老宿主缺少自动接入标记导致后台漏跑 | 新接入按原标记启动；旧机器池宿主通过认证心跳响应按 `singleTenant` 标识，不要求逐台补标记。非池宿主明确关闭此性能动作 |
| BBR初始化失败中断新接入 | 性能失败显示pending／内核不支持，接入继续；Agent独立跟进，BBR不作为可售门槛 |
| 仅等待不能解决模块／工具／配置问题 | 先加载当前内核模块；缺少模块加载器时只安装固定kmod工具，包锁和签名／配置镜像保持；必要时刷新原索引后重试。旧模块索引重建后重新加载并回读；程序配置漂移只追加固定BBR值，不截断管理员内容 |
| 可选qdisc／持久配置失败挡住实际BBR | 宿主算法与qdisc、持久化独立应用／验证；实际生效与持久成功分开报告，冲突继续跟进。未知自定义文件保持，不能伪报持久成功 |
| 到期任务忙误记已停机 | 任务／快照／代理操作忙继续保持占用，记录待停止；下轮空闲核原身份、实际stop并回读Stopped |
| 客户BBR范围错误扩大 | 删除客户namespace、Incus清单和客户sysctl路径；生产代码只操作固定宿主procfs键，不启动／重启客户 |

性能单轮45秒，轮后60秒继续；工具安装和索引重建失败采用10分钟退避。不存在无限安装器重放、包锁删除、换内核或客户重启。已开启的运行内核是条件；确实缺少BBR模块／不支持或不能安全修改的场景继续保留原算法正常售卖，不把pending当成功。后续环境修复后后台会重新加载与核验。

## 范围与后续

本轮通过的是源码、隔离PG／HTTPS、实际x86_64 Linux宿主内核与受控依赖修复；未连接生产、未提交／推送／发行／OTA。全部实际池宿主升级并核终态、ARM原生BBR、真实包管理依赖缺失恢复和正式新包升级还需独立证据。

到期控制面维持系统suspended，Incus实际Stopped而非Frozen；系统封停满72小时仍不续费则自动删除，客户磁盘／转发清理确认前库存保持占用。巡检五分钟，失联／任务忙／身份变化时保留具体失败并安全续接，不能保证失联期间立刻远程执行。
