# 自动快照持久恢复

自动快照先提交包含原实例/owner/host身份、唯一远端快照名与固定轮换目标的操作，再发远端请求。新快照存在并确认后，才删除原轮换目标。创建失败保留旧快照；远端成功SQL失败或进程退出后复用同一快照名和删除清单。

每实例最多一个未完成操作，pending/applying/retry/blocked均阻止实例转移、删除、重建及手工快照修改。实例/宿主行锁与操作锁下重读状态、归属、原宿主证书、Incus UUID、配额和原策略。取消/禁用只能在尚未发生远端写入前结束计划；一旦开始尝试，须核验原计划到终态，禁止丢弃不确定远端结果。

每次执行总时间有界；最多五次自动尝试，失败保留脱敏原因和下一次重试时间，之后由原实例当前授权用户在快照页重试。原身份不符时不自动改写身份。策略更新不清空已有操作，重试也不得重新选择要删除的快照。

恢复成功将新快照、旧快照删除、策略运行时间与成功日志同事务提交。通知在成功提交后发送。进程在通知发送边界退出可能丢通知，不能把该边界当成远端或数据库失败而重复创建快照。

证据须分别记录真实PG、mTLS API边界替身、真实Incus磁盘和生产执行；本文件是实现约束，不是验收通过声明。
