# v1.8.0 主控网页实测流程

供 owner 更新后逐项点击验证。全文不需要 SSH、命令行或直接改数据库。是否已正式发行，以 HANDOFF.md 和 GitHub Release 为准。

## 先准备测试记录

已有 Host 30 / Host 32 先只观察自动恢复。主动换机、删除、销毁及到期测试使用可丢弃的测试实例，不用正在服务客户的实例来制造故障。准备一个测试用户、能收邮件的测试邮箱，以及两台同 CPU/内存/磁盘/架构且符合区域条件的宿主；创建/购买实例走现有网页入口。

记录实例编号、名称、宿主编号、区域、价格、到期时间、余额、可售台数和时间。宿主“已分配磁盘”是配额，“存储池已用空间”是实际占用；两者要分别看。回收完成的最终依据是后台核验回执，而不是某个数字先变成零。

本机测试标签页关闭后，后台仍会继续已受理任务。重新打开仅查看进度，不重新提交同一任务。

## 1. 从主控更新

1. 管理员进入左侧“系统更新”（`/admin/system-update`）。
2. 在版本列表选择 **v1.8.0**，核对发行说明包含换机回收、历史源恢复、宿主管理认证修复和可读日志。按现有更新界面提交一次更新。
3. 在同页任务进度与更新日志中等到成功；重新进入页面核对当前版本 **1.8.0**。如果任务失败或已自动回滚，保留该任务日志，此次不能算已安装1.8.0。
4. 更新成功后打开“机器池”（`/admin/host-onboarding`）和“日志”（`/admin/logs`）。先观察后台自行处理，不点重装、不生成新的 Agent 安装命令、不手工解除隔离。

自动修复 worker 启动约10秒后开始扫描，完成一轮后约30秒再扫描；每队列分批处理。网络失败会退避，界面及日志给出下次检查时间，因此不是承诺所有宿主30秒内完成。

## 2. Host 32 / chuncheon-amd-4 自动恢复

1. 在机器池搜索 `chuncheon-amd-4`，查看在线状态与自动恢复状态；点击宿主名称进入详情（`/admin/resources/hosts/32`）。
2. “基本信息”观察 Agent 版本、最近心跳及连接状态。预期原来持续认证失败的 Agent 自动恢复心跳，版本仍可为 **v1.0.4**；这次是认证修复，不要求再升一个 Agent 版本。
3. 回到机器池观察宿主 IPv6 行。地址应在“公网 IP / OCI 账号”的下一行，纯文本，无复制按钮；多个地址分别显示，未取得时只显示“—”。
4. “日志”设为更新时间以后的范围，搜索宿主名或 `#32`。查看“宿主管理自动修复”相关记录，展开完整内容：应包含核验原 TLS、补齐引用/对齐 Agent 配置、后续心跳核验及最终恢复结果。
5. 等到恢复完成后再查看空机销售状态。只有本来为空且规格、协议、网络等销售条件均满足，才应恢复可售；已售宿主不会因为认证恢复被释放。

**通过：**无需逐台 SSH 或重复“验证并连接”；原受信连接与最新心跳恢复，证书缺失/旧 Agent 认证失配不再导致循环失败。一次“修复已执行”还不等于心跳已核验，须看到最终结果和更新中的心跳时间。

**未通过时：**在日志中记录宿主、步骤、原因、次数、下次自动重试；保留保护让后台继续。不要通过重装或重新信任另一台机器消除报错。

## 3. Host 30 / chuncheon-amd-2 历史失败换机恢复

1. 在机器池搜索 `chuncheon-amd-2`，进入详情（`/admin/resources/hosts/30`）的“实例”标签。
2. 找到之前换机失败后仍留在此宿主的原客户实例，记录实例编号、名称、宿主、价格和到期时间。仅观察，不再次换机。
3. 从管理员“实例”进入该实例详情（`/admin/instances/<实例编号>`），打开“网络”，观察公网 IPv6 是否从长期“正在配置”变为实际地址。然后用原客户会话在用户网页查看同一机器的“网络”。
4. “日志”搜索 `#30` 或宿主名，查看“换机原客户机器已恢复”。预期后台核对历史交付、原实例身份、实际地址和转发后恢复就绪。
5. 回机器池核对仍为该客户占用；价格、到期、余额、实例归属保持，不能把正在运行的原客户机器计入可售库存。

**通过：**原客户实例继续保留，故障隔离/错误就绪标记自动解除，用户端显示 IPv6，原磁盘和已售库存不被删除或释放。

网页地址显示与后台网络核验能证明本次状态恢复；不单独证明所有公网运营商的入站可达性。若要核对客户业务可用，可在浏览器打开该测试实例原有的公网 IPv6 Web 服务。没有现成 Web 服务时，此项标为“公网业务未测”，不用 SSH 临时改客户机器。

## 4. 主动换机：原实例、磁盘和库存回收

1. 在“机器池”或“实例”中选一台可丢弃测试实例。记录源宿主、当前实例名、价格、到期和该区域可售台数。
2. 源宿主详情的“存储”记录存储池已用/可用空间；有快照的测试实例记录快照数量。不要把整台宿主的镜像缓存或其他数据空间当作本实例系统盘。
3. 管理员实例详情点“更换机器”；或机器池该宿主菜单点“故障换机”。选择同配置备用宿主。
4. 按实际测试目的选择已有异地备份，或“重新创建系统”。重新创建会得到全新系统，不会搬迁旧机当前磁盘；仅在测试实例上勾选原有重建确认并点“开始换机”。这是首次换机授权，之后旧机回收不需要再次确认。
5. 观察换机完成，核对实例归属移至目标宿主、公网 IP 更新、原价格和到期不变、没有重复扣费。
6. 立即切到其他页面或关闭弹窗，再重新打开机器池。源宿主应自行进入清理、核验阶段；打开自动恢复进度仅用于观察。
7. “日志”搜索源宿主名/编号，查看每轮回收及“宿主自动回收完成”记录。最终内容应确认原实例、系统卷/快照和转发已清理，空机资格通过。
8. 源宿主“实例”页不再出现原实例；“存储”刷新后，原系统盘实际占用释放。源宿主恢复可售，目标宿主保持已售；同一区域换一台时最终空机数通常恢复至换机前水平，不能多释放一台正在使用的机器。
9. 用另一台测试实例的开通页面查看该源宿主所在区域库存；如需验证真正可重新分配，用测试用户正常开通并确认交付成功，随后按第5节删除回收。

**通过：**新机交付成功和旧机回收分别有证据；无手动 stop/delete、无人工恢复库存。guest消失但卷尚在时，界面须继续处理中且不可售，不能提前报完成。磁盘空间不会要求整盘归零，镜像缓存/系统文件仍可占用。

## 5. 管理员完整删除：不退款

1. 选一台可丢弃测试实例，记录用户余额、实例账单、宿主资源和库存。
2. 管理员“实例”进入详情，点原“删除”入口并完成该入口已有的初次删除操作。不要选择“仅移除数据库记录”。
3. 返回列表/关页后重新打开。“已受理/自动处理中”表示后台继续，不表示已释放。
4. 在“日志”搜索实例名/编号及宿主编号，观察删除受理、重试（如有）、最终删除和空机核验。
5. 核对原实例不再占用，宿主实例列表和存储反映释放，可售库存按实际空机恢复。
6. 核对用户余额不增加，没有新增此次退款账单。

**通过：**管理员不需要用户邮箱验证码；实际删除、资源释放和无退款均符合预期。

## 6. 管理员批量删除与退款选择

1. 宿主详情“实例”标签中勾选测试实例，点批量删除；确认“完整删除”和此次选择的“退款/不退款”。一机一卖宿主通常只有一台客户实例，不为了凑批量把同一宿主再卖给另一客户。
2. 提交一次后切走页面，稍后查看逐项结果、日志与库存；“自动处理中”不得显示成全部完成。
3. 不退款场景核对余额/退款账单无新增；退款场景核对实际删除确认后才退款，只有一笔，返回页面/刷新不会再次退款。
4. 管理员“账单管理 → 实例”中的“删除并退款”可另测全额/剩余价值规则，各用新的测试实例；以页面真实退款预览和原账目上限为准。

**通过：**每项独立处理；一项未完成不会丢失其余已受理任务。若当时没有离线/锁冲突机器，此轮记录正常批量通过，不谎称完成过故障注入。

## 7. 用户自行销毁：单台与批量

管理员登录不能代替真实用户销毁权限测试。本节仍全程网页：用单独浏览器会话登录测试用户端。

1. “我的机器/实例”选测试实例，点“销毁”，按原流程发送并填写账户邮箱验证码，提交一次。
2. 不输入/输入错误验证码应被拒绝；正确验证码只对本次账户和实例集合有效。不要把邮箱确认误认为后台自动重试还需确认。
3. 关闭弹窗或切页，再由管理员看日志、宿主和库存，等最终资源释放。
4. 检查测试用户余额没有增加，也没有销毁退款账单。免费、付费和错误状态实例都遵守不退款。
5. 另选两台符合销毁条件的测试实例测试批量：一份本次集合的邮箱验证码，逐项结果显示完成/处理中/未受理；已接受任务不需要再次点击销毁。

**通过：**原邮箱保护不被绕过；受理后的清理自动继续，释放前保留占用，不退款。

## 8. 到期未续费、宽限期和续费保护

1. 打开“账单管理”（`/admin/billing`）的“到期实例巡检”，查看“自动巡检已启用”、最近开始/结束、下次巡检；“日志查询”能查历次结果。
2. 选一个自然接近到期的测试实例，在用户网页关闭其自动续费。记录准确到期时间；不要改全局服务器时间、客户到期日或数据库来加速。
3. 到期后等自然五分钟巡检，预期先到期封停且资源继续占用。可点“立即巡检”触发一次，但另保留一轮自然自动巡检的记录，证明不依赖按钮。
4. 封停未满三天时仍应保留实例与磁盘，不能提前恢复可售。**满三天仍未续费**后，由巡检自动删除，核对日志、存储和库存，方法同第5节。
5. 用另一台到期但尚未超过宽限期的测试实例在用户网页正常续费；记录新到期时间和成功账单。下一轮巡检不得按旧到期时间删除它，库存仍占用。
6. 再用开启自动续费且余额足够的测试实例观察到期续费成功；检查扣款一次、新到期时间与没有误删。余额不足场景应显示明确原因并沿原到期规则处理。

**通过：**先续费判断、再到期处理；三天宽限不变，删除失败不释放库存。没有现成已满三天的测试实例时，这项需要实际等待，记录“待到期/待宽限期”，不能用点一次巡检当作整项通过。

## 9. 自动恢复不依赖页面、日志能读懂

1. 任选一项已受理且尚在处理的测试删除/回收，关掉相关弹窗甚至登出；稍后重新登录查看任务和日志。
2. 原任务应继续，而不是回到“尚未开始”；临时读取失败后页面自己重读；不出现靠“等待确认/重新检查”推进后台任务的正常流程。
3. 在“日志”分别搜宿主名、`#宿主编号`、实例名，以及“到期巡检”“自动修复”“自动回收”。时间范围要覆盖该次操作。
4. 查看旧巡检记录和新记录：操作名称可读，正常开始为“已开始”，结果说明本轮失败数量；JSON字段名、内部操作码不应直接占据主要描述。
5. 自动操作记录显示目标、步骤、原因、执行结果、次数和下次自动重试；完成有终态记录。失败保留原原因，不能用“成功”隐藏未完成。
6. 手机宽度和明暗模式各看一次：长地址和日志可读、内容可展开，无新增IPv6复制按钮。

系统无法确认原身份/权限或仍有未知数据时，会保护数据并自动重新核验；自动化不能承诺将真实冲突强行变成成功。此类情况记录确切原因和时间，不通过反复确认、重装或删除未知实例“通过测试”。

## 10. 仅移除记录的对照（可选）

这个模式刻意保留远端磁盘，不是本次自动释放路径。若确实要测，仅使用单独可丢弃测试实例：选择“仅移除数据库记录”，预期后台记录移除、宿主隔离且不可售，远端磁盘不被自动删。**本轮不提供把这一模式留下的未知磁盘强行自动删除的网页流程**，没有测试必要可以跳过，避免主动制造需另行处理的保留数据。
