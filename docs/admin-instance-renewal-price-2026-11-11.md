## 使用与结果

管理员进入用户实例详情，在「信息 → 基本信息 → 续费价格」旁点击铅笔，读取当前价格后保存新金额。按实例独立保存最终每期续费价，范围 0–100000 元，最多两位小数；零元有效。保存后下一次手动、批量或自动续费使用新价，不叠加 AFF／会员优惠。周期沿用实例当前周期，用户手动续费仍只展示一个月。

已付款账单、余额、当前到期时间、客户身份、库存及商品／其他实例价格保持。保存只更新该实例的 `renewalPrice`、版本与更新时间，并在同事务记录操作者和前后价格；不补扣、不退款、不启动客户或重新交付。

新 nullable `renewal_price DECIMAL(10,2)` 列无历史回填，数据库约束 0–100000。未设置的实例继续原计价；原 `billingPrice` 保留，退款仍根据历史实付账单计算。正常重装、换机、迁移沿原记录更新，不清空最终续费价。新建的另一实例不会自动继承该价。

## 代码审视和精修

1. **类型阻碍**：`hosts.ts` 原价格修改的并发条件使用 `Prisma.DbNull`，缺少 `Prisma` 导入；已修，服务端类型／构建通过。
2. **权限和并发**：API 使用生产管理员鉴权；事务再核数据库当前角色、账户、会话撤销、实例归属／宿主／客机／版本。复用续费／到期串行通道及实例 advisory/行锁；恢复、删除／清理、保留期截止、转移／任务、快照／反代及宿主维护阻断。提交前再次核保留期与恢复保护。忙立即返回，旧弹窗需重新读取。
3. **最终价与历史实付分开**：手动／批量／自动续费按最终价计算，AFF／VIP不能再次折扣或产生AFF续费返利；旧差价结算入口拒绝覆盖已设置最终价的实例。两处宿主退款调用误传下期价已恢复原实付价格。实际退款算法本来已有历史账单保护，专项没有复现“零元下期价导致退款归零”；这是调用口径精修，不宣称此前已发生退款事故。
4. **旧报价**：手动和批量提交实际显示的金额，服务器在扣款事务内比对。单台价格变化返回 `RENEWAL_PRICE_CHANGED`，批量按实例保留明确失败原因及成功／失败回执。旧报价未扣款，重新打开窗口读取后再确认。
5. **丢失续费回执后改价**：已用浏览器复现原实现把 `expectedAmount(s)` 纳入请求身份，刷新为新价会生成另一个编号。现把报价作为前置条件，原用户／目标／月数构成同一持久意图；网络结果未知或在途时保持原编号。已完成请求即使价格变化也返回原账单金额，不重复扣款。只有明确的服务器扣款前价格拒绝可清编号；账户及月数仍分开。旧稳定版没有报价字段，原持久编号继续兼容。
6. **界面和生命周期**：管理员编辑器只进入管理员包；请求和回执绑定当前会话／目标／原归属／宿主／客机，换目标、撤权、会话ABA、卸载及本地存储变化拒绝迟到结果。补 native dialog 的 Tab／Shift+Tab循环、初始焦点和关闭后焦点恢复，保存中禁止普通关闭。用户续费弹窗同样拒绝旧目标／会话报价及成功回执。金额、周期、失败与影响说明三语一致，保留原黑白样式和至少44px控件。
