# v1.8.1 网页使用与验收

本页对应购买付款与普通 OSS 整库还原。具体发行身份和已完成验证见 [验证记录](release-v1.8.1-validation.md)。所有生产付款、升级和还原由 owner 自行安排；下述步骤尚未在生产代为执行。

## 网页升级

1. 超级管理员进入「版本更新」（`/admin/system-update`），点击「检查更新」，确认最新版本显示 **v1.8.1**。
2. 点击「更新到最新版本」，在确认框确认目标版本为 **v1.8.1** 后提交一次。更新会备份当前版本、执行数据库迁移并重启主控服务。
3. 在同页等待更新任务成功；重新打开页面确认当前版本为 **1.8.1**。若显示失败或自动回滚，以任务实际结果为准。
4. 打开用户端商品页和管理员「阿里云 OSS」。正常升级无需执行还原；下节仅适用于主控故障后迁至新机器。

## 正常 OSS 异机还原

适用：原主控 A 已故障，B 已安装兼容版本，B 同时担任主控与网关。保持正式运营原域名，由 owner 先把原域名解析指向 B。

1. 登录 B 管理后台，进入「阿里云 OSS」，保存 OSS 资料。
2. 从列表选择所需时间的完整备份包，点击「还原」。已保存的备份密码自动复用。
3. 页面自动显示预检、数据还原、网关和宿主连接、业务恢复的进度。无需人工补账、逐台填写宿主参数或再次确认恢复运营。
4. 等待页面明确显示还原完成。暂时断线会自动退避续接；关闭页面不会取消后台任务，重新打开可查看保存的进度。
5. 完成后使用备份中的原账号登录。管理员在机器池查看原宿主连接和 Agent 心跳，在用户机器页查看归属及运行状态；用户可从自己的机器详情管理原实例。账单、余额、订单、到期时间回到所选备份时点。

还原期间客户实例保持原状态，不重建客户磁盘。备份后的交易和客户磁盘内容不由平台数据库备份生成。原宿主离线、原身份或磁盘丢失、真实网络冲突尚未消除时，不会将其伪装为还原成功。

## 购买与付款

1. **直接购买**：商品页点击「直接购买」，独立确认页仅包含这次商品；原购物车不受影响。
2. **余额**：选择账户余额，点击一次「确认并付款」。系统扣款并自动交付；不显示第三方待付款，也不再要求二次确认。
3. **支付宝 / 微信 / USDT**：选择已配置方式并付款。服务端确认到账后自动交付，购买款不先充值到账户余额；页面显示交付进度及结果。
4. **更换方式**：在未付订单返回并选择另一方式。手续费随当前选择更新；旧未付尝试不阻止新选择，付款期限不会无限延长。
5. **购物车批量**：加入多台后从购物车统一结算，一次付款后自动交付整批。关页后可从「订单→购买订单」继续查看。
6. **清空重买**：清空购物车后重新下单，不要求完成旧未付单。已关闭订单的迟到付款不会重复交付，按原收款记录保留退款处理。

真实付款验收只使用专用测试账户及小额商品，完成一次付款后刷新订单确认没有重复扣款或多创建机器。外部收款退款沿原渠道处理，不转换成钱包充值。

## 验证边界

本次保存了源码、隔离 PostgreSQL、真实备份本机导入及页面证据；Linux 双架构首装、正式资产以验证记录中的最终结果为准。独立真实 OSS 新 B 全流程、原宿主真实隧道重连、客户持续连接、千台真机与 72 小时仍分别验收，不能由安装或 CI 成功推定。
