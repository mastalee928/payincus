# GRUB 自动加固修复与验收

本阶段修复已写入正式程序源码；线上运行结果仍以 HANDOFF.md 最新记录为准。

## 修复

- Alpine 生成的 GRUB 配置允许原始 `0700`，原子修改和条件回退均保留原权限；不允许组或其他用户写入。
- 依赖准备分为规划、安装、规则编译、引导准备四轮。先持久保存原包清单及官方同分支精确版本，安装独立限时，单线程规则编译另轮执行。
- AppArmor 的 tunables、abstractions、API 拆分规则包一起准备，避免工具存在但 Incus 网络规则无法加载。
- 中断安装只接受已规划新增包的子集；原包替换、额外新增包、最终缺包均拒绝。完成后仍核完整清单，不能由工具存在绕过。
- 过期未知准备只查询结果并按原配置条件回退，不重放准备。安全回退后保留原身份和请求，等待旧请求失效，最多两次重试；耗尽与前置失败持久显示具体原因。
- Btrfs 明确报告动态 inode 时避免误拒绝；普通文件系统零 inode 仍阻断。已修复且实际监听当前版本的客户只验证，不重复更新。

## 已完成实验

两台隔离 Alpine 3.24.3 VM 使用实际 AMD64/ARM64 内核、GRUB、Incus 7.0.1 和非特权持久客户。QEMU 使用 TCG，无 KVM；这些结果不等于原生硬件或生产验收。

最终源码从未启用 AppArmor、缺少六个依赖包的独立基线完成准备、单次重启和客户恢复，期间未手工重启 AppArmor/Incus 服务。旧实验中缺规则包导致的失败及手工诊断结果保留，不计入最终成功。

两种架构均核验：新 boot ID、AppArmor 实际 enforce、原 UUID/UID/GID、shadow/passwd/SSH 密钥/客户文件及 `0640` 权限、原自启设置、原客户 IP 和网关连通、Seccomp=2。使用原受信客户 SSH 密钥完成原密码登录、SFTP及持续连接检查，错误密码与 5000 字节错误密码拒绝。加载实际 Incus profile 的进程被内核拒绝打开宿主敏感入口，只打开未写入，不触发系统动作。

本机 13 项 Python 维护回归、受限网关回归、真实隔离 PostgreSQL 维护/客户恢复/SSH维护/队列专项、相关安全守卫、后端类型与构建通过。日志保存在本地忽略目录，私有实验资料在仓库外。
