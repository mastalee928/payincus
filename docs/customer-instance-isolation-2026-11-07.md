2026-11-07。范围为禁止客户特权容器、堵住平台配置入口，以及原受信通道的线上只读检查。本轮没有生产部署、重启宿主、停止客户或修改密码。

## 线上实际检查

北京时间 13:12 沿原管理 SSH 指纹与 Incus 证书检查 28 台在线、已成功接入宿主，无检查失败。本次只检查这些宿主，不把离线、未接入或未登记机器计为通过。

- 实际发现 2 台运行客户容器，均非特权、未启用嵌套。seoul-amd-2 的实例 #28 与 londom-amd-1 的实例 #27，客机 root 的实际 UID/GID 均映射到宿主 1000000，Seccomp 为 2（过滤模式）。seoul-amd-3 无客户实例。
- 两台客户的有效配置以及本次读取的默认 profile 未发现 raw 配置覆盖、系统调用保护修改、宿主磁盘/设备或 Unix socket 转发。检查不读取客户文件、密码或运行内存。
- 28 台宿主的 AppArmor 未启用，读取的 LSM 列表没有 AppArmor。非特权和 Seccomp 仍有效，但缺少这一层强制访问控制；需要专用环境验证内核/启动支持、Incus 和客机兼容性后，再安排生产维护。源码检查不会自动启用内核功能或重启宿主。

本地脱敏证据在 ignored `logs/customer-isolation-readonly.json`，真实连接资料不进入公开文档。配置核查不是漏洞利用测试，未发现特权设置不等于证明不存在逃逸漏洞。

## 本轮源码保护

1. 套餐创建/编辑和批量 API 拒绝启用特权，管理员也不能绕过。管理界面移除特权开关；旧套餐的标记不会直接改变现有客户，保存时写回非特权。旧特权套餐进入开通/重装/换节点时拒绝，避免自动交付特权客户。兼容数据库返回的非特权数字 `0`；已禁用的默认套餐初始化也改为非特权，避免未来重新启用时违反政策。
2. 新建容器显式 `security.privileged=false`、`profiles=[]`，所有网络和根磁盘设备显式生成。不会继承默认 profile 的特权、raw 配置或宿主挂载；旧调用没有静态 IP 时也有显式 NIC。KVM 保留原代理配置盘和网络。
3. 配置更新/新增及删除设备、启动/重启/解冻和重装检查客户隔离。读取有效配置和实际 profile，拒绝原始 LXC/AppArmor/seccomp/idmap 覆盖、关闭默认 syscall 保护、宿主设备/目录、Unix socket 代理和客机向宿主服务反向绑定；拒绝宿主 root 映射以及额外 mount/BPF 拦截授权。删除实例配置的空值不能掩盖继承值；删除设备也不能重新暴露同名 profile 的宿主挂载。
4. 复制前后检查隔离，仅复制实例，避免附带历史危险快照；快照恢复先核原实例和快照。备份流导入后、替换原实例前检查隔离；失败保留原实例、副本和原任务门禁。恢复身份哈希、原磁盘/网络、库存及账务断言保持。
5. 嵌套功能仍可在非特权容器使用；修改容器权限属于管理员配置。客户正常 root、原密码和 SSH 配置不会因本轮隔离检查被改写。
