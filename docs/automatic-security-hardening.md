# 新版全自动安全加固：统一方案与实际进度

2026-11-08更新：下一版安装/升级后自动维护已有宿主和客户，新对接在交付前完成加固。正常流程不需要管理员逐台操作；owner已接受必要宿主重启带来的短暂客户中断。持久队列、维护编排、新对接门禁与网页详情已有源码和对应隔离证据，本轮按owner授权精修后推送源码分支，实际SHA及Actions见HANDOFF；自动重启的原生验收白名单仍为空，不会由本轮代码开启生产重启。本文件区分目标、实现与实际验收。

### 架构要求：AMD64与ARM64分别验证

- 同时覆盖AMD64/x86_64和ARM64/aarch64。分别探测主控/网关、目标宿主、客户镜像及组件架构，混合架构部署按实际目标匹配；不能因主控是AMD64便给ARM宿主下发AMD64二进制或镜像。
- 按实际ARM系统核内核/引导器、AppArmor/LSM、Seccomp、容器UID/GID映射及VM/KVM能力；内存页大小和资源阈值由目标探测，不照搬x86假设。每个自动维修方案明确已支持系统/架构与验证范围。
- ARM64须独立验新接入、已有宿主/客户加固、必要真实重启和断线续接、原密码及网络恢复、低内存检查/更新峰值。AMD64测试不能替代ARM64运行证据；构建成功也不能替代重启/内核/客户实际流程。
- 下一版两个架构的实际安装包同源码核模板、脚本、原生依赖及组件架构，分别验首装和OTA。已有Alpine3.22 ARM64 SSH补丁证据仅证明该补丁范围，新自动加固全流程仍待实现与验收。

## 1. 已有宿主：升级后自动分批维护

平台初始化且恢复保护解除后启动持久队列。每台先核当前授权、原宿主/客户身份、系统与内核支持、客户实际状态、有效配置及任务冲突。维护期间阻断该宿主新增交付和冲突操作，不阻断其它正常宿主业务。

自动应用适用的官方签名SSH补丁，保留原密码认证、账户、配置和主机密钥。AppArmor等项目先判断可解决原因，准备并验证适用配置；确需重启时由系统逐台执行，前台管理员无需点击。前一台重连和验收完成后才继续下一台，不同时重启整批宿主。

重启前记录原运行/停机客户和身份、转发等核验基线；重启后依最新账務/停机/删除意图恢复原运行客户，原停机及平台封停客户保持停机。临时自启覆盖先落盘，完成恢复验收才用条件修改还原原值。沿原管理身份重新连接，核Incus/Agent、客户隔离、SSH、IPv4/IPv6及端口转发。原磁盘、密码、名称、归属、额度、已付到期和账務不修改，不重建客户。

维护准备、远端自启修改及恢复动作都要求实际Incus客户明确为持久实例（`ephemeral=false`）；临时实例停止会被Incus自动删除，缺失或非布尔属性也不能取得维护权限。拒绝时保留原实例，不自动转换。宿主维护获节点锁后重读完整管理身份，等待期间地址或绑定改变即阻断。新接入完成独立重查当前故障/IP/独占模式，不从旧成功回执清除凭据或标可交付。

SSH补丁重载继续以原连接保持为目标；宿主重启会中断客户连接，两种证据分开记录。不得称宿主重启全程无感或零中断。

## 2. 新对接：验收后才能交付

管理员正常填写接入资料后，系统自动完成检查、接入、安装、SSH补丁与隔离防护准备、必要重启、原身份重连和安全/网络验收。加固检查应直接纳入接入任务，不靠接入完成后的后台扫描补救。

未验收通过的宿主不得标接入成功或进入可售池，任务明确显示检查/准备/重启/等待重连/验收阶段。失败自动有限重试，仍失败则保留具体原因并阻断交付，不让未加固宿主先承接客户。

客户新建仍显式非特权并检查实际有效profile/config/device，不能通过raw配置、宿主挂载/设备/Incus socket绕过。Alpine客户初始化核官方SSH补丁及实际监听进程，保持密码登录。

## 3. 自动动作与不能继续的条件

| 情况 | 系统处理 |
|---|---|
| 适用SSH官方安全修订 | 原身份/密码预检后自动安装、重载、验证 |
| 已验证可通过配置及重启启用的防护 | 自动准备、逐台重启、重连验收 |
| 任务忙、短暂断网、重连等待 | 持久退避续接，避免重复写和重复重启 |
| 不支持的内核/引导配置、原身份变化、未知客户/数据冲突 | 不盲改或盲reboot，保留明确阻断原因 |
| 已有特权客户需转换 | 单独核转换方案；重启授权不等于允许改磁盘/类型 |
| 补丁连续失败达到上限、重启后未恢复 | 停止进一步更新/重启，保留错误和恢复步骤 |

正常适用流程全自动；硬件/系统不支持、失联或身份冲突不能保证自动修复。“需处理”仅用于系统确实不能安全继续的情况，不以“需要重启”为人工操作理由。

队列必须持久记录维护租约、原身份、准备回执、重启意图及原启动标识，断线或主控重启后可判断操作是否已执行。重启命令回执不等于重启完成，断线不等于已进入新启动；同一意图不得反复reboot。原权限撤销、恢复保护及身份变化仍阻断后续动作。主控灾备恢复期间不因此重启客户。

## 4. 管理员入口：查看进度与详细异常

入口放在管理端“机器池”每台宿主的“安全加固”状态，不新增一级菜单。点击打开详情，逐项说明当前防护、失败阶段、具体原因、受影响客户、系统已做动作、下次自动动作和无法继续的原因/解决步骤。客户实例详情显示自身隔离状态，并链接对应宿主详情。

常规加固自动执行，入口以查看为主，不要求管理员逐台点击“准备”“重启”。持久日志记录阶段与结果，只有无法自动继续时突出异常；不能只显示“需维护”三个字或一闪而过的通用错误。全部必需项目通过后才标已验证，部分SSH成功不能代替AppArmor或客户运行验收。

### 2026-11-07追加：复杂故障也按证据自动处理

Owner要求增加判断，棘手问题尽量自动解决。下列规则是本次审查补齐的实现及验收要求，尚未全部写入运行代码。每个自动修复方案必须规定适用系统、准确失败判据、允许动作、回退条件、次数/时限和独立复验；不能只增加重试次数。

#### 前置检查与维修范围

- 判断内核是否编译AppArmor、实际LSM列表与启动参数、引导器及原启动项、AppArmor工具/策略、Incus版本及实际配置。区分未安装、未启用、策略未加载和进程未受约束；仅在已验证配置能解决时准备和重启，缺失内核支持不能通过reboot补齐。系统/架构对应方案先隔离验证，不能自动跨发行版或盲升级内核。
- 检查根分区和启动分区空间、inode、只读状态、包管理进程/锁、包数据库一致性、配置语法、原SSH监听和受信备用管理路径。清理仅限本任务拥有且已结束的临时文件，核绝对路径/归属/符号链接；不能自动删客户磁盘、快照、日志或其它更新目录来腾空间。
- 识别目标是否承载唯一主控或活动网关。不能直接套用普通客户宿主重启流程；必须先具备独立可用的受信执行/恢复通道及持久回执、验证重启后续接。缺少这些条件时说明具体阻断原因，不能关掉唯一维修通道。
- 客户容器与VM分别验证。容器核全部UID/GID映射、实际PID/startTicks、AppArmor enforce策略与Seccomp规则；Seccomp数字2本身不能证明规则符合要求。VM核实际QEMU身份、设备/宿主路径、AppArmor及可用的沙箱机制，不能因未列入容器PID清单便认定防护通过。
- 自定义发行版、SSH/PAM/监听参数、缺失登记或客户已自行更改原密码，须先证明支持的受限维护/核验路径。不能重置密码、覆盖客户配置或重新生成管理身份来取得成功；没有适用验证方法时明确尚未支持。

#### 故障判定与固定修复

| 故障 | 必须取得的判断证据 | 自动处理与复验要求 |
|---|---|---|
| 更新源超时、DNS或短暂网络失败 | 区分解析、连接、TLS、签名及版本不存在；确认包管理器是否仍在运行 | 原受信通道退避；仅在已验证的同发行分支官方可信源范围切换，保持签名/版本校验。签名错误或来源异常停止写入，不降级为不可信安装 |
| 包更新中断、进程超时、残留锁 | 远端任务journal、boot_id、PID/startTicks、实际包/监听版本、包数据库及原配置hash | 仍运行则等待并核状态；已结束且本任务确有所有权、一致性检查通过才处理自身残留并续接。租约/网络超时不等于远端进程停止；现有无所有者的旧锁不能按超时盲删 |
| 补丁已装而监听仍旧、重载失败 | 实际监听二进制/PID、配置语法、包修订、原账户/密钥/配置及原连接 | 仅执行已验证的同服务恢复步骤；复验原密码新登录、错误认证拒绝和原连接。必要重启走持久维护流程，不降回漏洞包，不强制杀未知更新进程 |
| 管理路径部分失联 | 分别核SSH、WireGuard、Incus TLS、Agent心跳/服务及原身份，区分单通道失败与整机失联 | 通过仍可用的原受信通道恢复已验证的受管组件或管理配置，保持原客户网络。不能仅凭ping或Agent上线认定全部恢复，不能清pin或自动接受新证书 |
| AppArmor未生效或客户进程未受约束 | 内核/启动参数、策略加载结果、实际进程标签、有效配置及拒绝行为 | 适用方案自动安装/加载或准备必要重启，再验证运行中的容器/VM。自动修正仅限平台拥有且已验证的防护配置；不把关闭AppArmor/Seccomp或启用特权当恢复办法 |
| reboot响应丢失、主控重启、同请求重放 | 原/新boot_id、远端持久请求id/准备hash/阶段、原管理身份 | 查询已执行结果后续接；同一意图最多进入一次重启执行。若需第二次重启，必须重新诊断并生成独立、受预算约束且可审计的维修计划，不能因等待超时重复reboot |
| 重启后Incus/客户/转发未恢复 | 原客户运行状态及身份、Incus操作状态、存储挂载、服务/管理握手、实际转发/客户连接 | 固定顺序恢复已验证的受管服务，等待正在进行的Incus操作，恢复原运行客户并逐项验收；原停机保持停机，原suspended须验证可保持/恢复的检查点方案，不一律start |
| 本任务修改的配置导致恢复异常 | 原子备份和前后hash、当前文件归属、修改后是否存在其它写者、独立恢复通道 | 只回退本任务修改且当前仍匹配的配置，再复验；出现他人新配置时停止覆盖。应用OTA回滚与安全修复分离，不恢复已知漏洞或覆盖客户磁盘/新账务 |
| 同类故障连续出现、修复用尽或整机无法启动 | 每台/每阶段错误指纹、维修预算、恢复时限、批次结果，以及受信救援通道能力 | 熔断后续重启，仍可执行只读诊断和已验证的当前故障恢复。系统实际无法启动的自动救援须另有独立受信控制面/串口或救援通道及最小权限、原盘身份和专项验收；目前没有已验收能力，不宣称面板能自动救回全部失联机器 |

#### 持久续接、业务协调与批量熔断

1. 每个阶段保存计划revision、宿主/客户原身份、boot_id、请求id、准备hash、开始/结束回执、准确错误类别、修复动作/次数及下一次动作。远端journal须root保护，命令与回执绑定同请求及目标；主控DB恢复、旧组件或旧快照不能重放陈旧重启意图。原生重启后的续接使用新PID重新核身份，不能拿重启前PID作现行运行证据。
2. 调度租约只排队，实际远端动作由独立门禁和请求去重保护；短事务登记/核回执，不能持DB事务跨重启。销售、购物车占用、交付、启动/停止/重装、备份/快照/恢复/迁移及删除等入口共用该宿主维护门禁，并复查执行时归属/授权，堵住排队后新任务竞争。
3. 续费、付款和到期账务继续依当前规则处理；与维护冲突的远端到期停机/删除意图持久排队，恢复时按最新支付/到期/删除授权重新判断。重启前running基线不能覆盖维护期间新生效的停机/删除意图，也不能使已续费实例误停或重复扣款。
4. 先单台验证，再按有限批次推进；全局及同故障域限制在途重启数，前一台完成或明确进入阻断恢复后才决定下一台。相同严重失败、恢复超时或可用容量不足熔断后续变更；部署前给出按系统验证的时限/阈值，不能靠无上限循环等待。
5. 忙/离线等待与真正的补丁失败分别计数，host/步骤具有独立预算；未知错误先只读诊断，不能自动授予新的写动作。耗尽后在权限/身份保持且可证明故障条件已变化时生成受控新计划，不要求管理员手动清JSON，也不能每次扫到坏机重置预算。坏宿主不得饿死其它宿主检查；共因熔断仍须保护整批。
6. 全部验收项绑定当前策略revision/组件/启动身份；维护失败或证据过期不能显示已加固。新对接在安全、管理连接及客户交付必需网络验收通过前不得成功或可售；已有宿主失败保留该宿主交付门禁和准确原因，不能将其它宿主一并停用。

#### 必须补做的故障注入

定向覆盖更新前/中/后断线、更新/重启请求回执丢失、主控进程退出、重复租约/请求、旧数据库回执恢复、包锁仍活及自身残留、磁盘满/只读、策略加载失败、SSH/WG/TLS/Agent单路径失败、重启后Incus启动慢/客户原运行与停机及暂停状态、同类批次失败、权限撤销与客户付款/续费/删除竞争。每项须断言目标身份/原密码/磁盘/客户网络及账务保持、没有重复重启或错误启动、不虚报安全验收；原生内核/引导/服务与公网恢复证据单独保留。

真正缺少内核支持、硬件故障、全部受信通道失联、身份冲突或无法确认的数据问题不能承诺全自动解决。页面应展示已经自动做到哪一步、剩余阻断证据及具体可行恢复方法。只有经过核验的固定修复可自行执行；重新信任、重装客户、放宽隔离或猜测式修复不属于正常自动处理。
