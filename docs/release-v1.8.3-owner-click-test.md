# v1.8.3 网页升级与检查

本版已[正式发行](https://github.com/mastalee928/payincus/releases/tag/v1.8.3)，同来源完整CI、双架构正式首装和六资产核验通过，见[验证记录](release-v1.8.3-validation.md)。本次由 owner 自行网页升级；维护 agent 没有执行生产 OTA、改隔离标记或操作客户实例。以下全部使用网页，涉及购买/转移时使用专用测试账户和已授权测试实例。

## 网页升级

1. 超级管理员进入「版本更新」（`/admin/system-update`），点击「检查更新」，确认稳定目标为 **v1.8.3**、源码短提交为 **1ac022b567ee**。先记当前版本与更新时间；此前只读目标已v1.8.2，不把旧版本的部署事实当成本版已部署。
2. 点击「更新到最新版本」，确认后在更新任务中等待备份、迁移、验证和唯一后台重启完成；重新进入，核当前版本 **1.8.3**、提交 **1ac022b567ee** 与新的部署时间。更新任务失败时保存任务编号、失败阶段和错误，查看该任务的验证/回滚结果，不以顶部提示当成更新完成。
3. 正常升级不需要 OSS 还原。本版没有新增数据库迁移，累计仍为240；Agent保持v1.0.4，不移动已有tag或重发原资产。

## 再次故障隔离及 IPv4/IPv6

1. 进入「机器池」，找到仍提示故障隔离的宿主，打开恢复检查。在线和心跳正常说明管理通道可达，不能单独证明恢复条件满足。
2. 旧清理任务已完成但宿主又被隔离时，新版后台创建新的**只读核验周期**，保持原宿主身份。等待自然后台巡检；可在恢复页面点击原有重试入口，仍只重核，不能重放旧删除授权。
3. 查看客户实例、在途任务、账务、磁盘/快照/转发残留及身份检查。空库存确认通过后应由程序解除隔离、恢复可售库存；已售客户恢复检查通过时保留原实例、磁盘和占用，不得变成可售。身份不符或未知残留继续隔离，页面与日志保留原因，不能手工清字段绕过。
4. 恢复条件通过后查看宿主 IPv4 和 NAT 配置中的 IPv6 状态。IPv4/IPv6各自按原身份和入口规则自动续接；若IPv6仍未完成，对照具体阻断原因，不连续点同步当作恢复。
5. 在「日志」按宿主名、实例编号和时间搜索开通失败、退款/清理和回收核验。新失败保留首次原因、失败时间、核验阶段及下次动作；历史缺失的具体失败步骤无法由新版补出。

此前只读诊断确认目标宿主未换IP，其再次隔离来自新实例开通失败补偿后旧done任务没有重新排队；另一宿主換IP成功是独立事实。此次未替 owner 改生产隔离、网络或库存。实际升级后须按以上步骤核结果，不能以发行CI代替生产恢复成功。

## 工单公网 IP 与 OCI 账号

1. 管理员进入「工单」，打开关联实例的工单。实例卡片 IPv4 应是当前宿主公网地址，不能显示 `10.x` 等客机NAT内网地址。
2. 宿主公网地址正在同步时显示当前受信观察地址；没有已知公网地址时显示横线，不回退到内网IP。
3. 展开「详情」，查看 **OCI账号** 标签，值来自已有接入账号名称；旧宿主沿原账号标签来源显示。这里只显示名称。普通用户实例详情不会返回该管理员字段。

## 首页与品牌标题

1. 用普通窗口打开首页；再缩短窗口高度，测试125%和150%缩放。桌面地图随剩余高度收缩，底部帮助和联系方式可达；极短窗口允许纵向滚动。
2. 手机打开首页，滚到底部并展开联系方式；检查菜单、地图/球体交互和三态主题仍可使用，不出现横向溢出。
3. 管理员在「系统→品牌与外观」保存网站名称和网站副标题。用户端刷新后从首页进入「创建实例」（`/purchase`），浏览器标签应为 **网站名称 - 网站副标题**；多次返回首页再进入仍保持当前配置。

## 说明图标与余额

1. 「实例管理」卡片的自动续费说明图标：电脑悬停或键盘Tab聚焦可读说明，Escape关闭；手机点击显示，再点击关闭。说明包含余额扣款、余额充足和转移后关闭自动续费。
2. 使用专用测试账户进入创建实例后的确认页或购物车。余额支付项应显示 **账户余额(￥100.00)**，金额与账户实际可用余额一致；尚未读取成功时显示横线。
3. 切换测试账户后核金额来自新账户；付款后核余额流水、订单及实例交付。支付通道、币种和付款流程保持原有行为，不将实时余额附加到历史付款记录。

## 实例转移

1. 使用已授权的一机一卖测试实例和两个测试账户，在「实例转移」发起PUSH，由目标账户接收。先记原实例编号、归属、月费、已付到期、公网IP与账户余额。
2. 在实例管理卡片查看「等待转移」或「转移中」状态。重复PUSH、续费、自动续费切换和冲突开关机操作应受限制，不能重复发起；刷新或重新进入仍能读得后台状态。
3. 在「实例转移」查看持久结果。数据库并发更新时，后台最多四次重新提交；仍冲突则保留阶段并退避，自然五分钟任务和后台重启后按原授权续接。页面显示人可读原因，不显示Prisma/SQL原始堆栈。
4. 转移完成后，新用户核实例归属、原磁盘/已付到期/月费及网络；转移手续费只记一笔。自动续费关闭，新用户自行决定开启，并按通知重置实例凭据。专属地址与原实例保持；原转移合同要求清理的快照、备份及建站反代按原计划执行，不把这些资源的预期清理误报为客户磁盘丢失。
5. 授权撤销、身份变化、新资源或不满足转移条件时继续保留原任务和原因；不能用重建客户、删除新资源或重新扣费“修复”。

## 接入与公网 IP 回归

1. 「机器池→新增宿主」输入已经正常接入的IP，应提示已在机器池，并能定位原宿主；不重新安装或创建重复占用。
2. 仅对已授权、无客户的测试宿主验证失败接入/重装重试。尚未建立正式Host时，用当前root密码点普通重试，检查当前系统认证、旧登记清理和新接入的持久进度；已有正式身份或客户占用继续受保护。
3. 无需为本版检查更换生产IP。核机器池、节点详情、用户实例卡片/网络与管理员工单的当前公网IPv4一致。已由owner在OCI换过IP的同一宿主应保持原实例、管理身份和账期；关机不因IP检查强制开机，另一机器当前占用未释放或身份不同不应伪装成功。
4. 无客户宿主的删除回收只有在实际实例、磁盘/卷/快照与转发清理确认后才能恢复可售库存；只隐藏接入历史不得断开仍在机器池的宿主管理通道。故障隔离始终先完成上方恢复检查。

## 支付回归

1. 专用测试账户在「创建实例」选地区、配置、镜像与数量，直接购买进入独立确认页；另一次加入购物车进行批量结算。切洲/地区后旧配置和金额立即失效，确认页金额与当前选择一致。
2. 余额支付项显示当前账户金额，确认付款后订单、余额流水和交付只发生一次。已配置的支付宝、微信或USDT测试通道付款，核到账后自动交付，购买款不先进账户余额、不要求第二次确认开通。
3. 管理员在订单/账单中对照测试账户的订单、实例、付款/退款、金额和到期时间；失败交付的退款不能重复，清理未确认的库存不能再次销售。真实通道重复回调只在独立授权测试通道执行。

## OSS 备份及还原检查

1. 超级管理员进入「阿里云OSS」（`/admin/aliyun-oss`），展开「连接与存储桶·备份设置」，核已有Bucket、区域、目录及已保存的备份密码状态。按页面「保存并测试连接」核本次配置就绪；凭据仅在网页输入，不写入工单、截图或公开日志。
2. 点击「立即备份」后，在「任务记录」等待实际备份/上传/完整性结果成功，记录任务编号、时间、版本与大小；刷新「备份与恢复」，确认该完整记录可见。开始或上传中不等于可恢复备份，失败查看具体阶段和原因。
3. 正常升级不点击还原。若owner另行执行已规划的专用B还原演练，先让原固定正式域名指向B；登录全新B保存OSS/解密材料，选择完整备份并点击「还原」。后台自动预检、恢复所选备份时点的数据库/配置/原管理身份，显示持久阶段与错误，并按原身份观察宿主和Agent自动重连，不逐台填写SSH或补交账目。
4. 还原后分别在机器池、测试客户实例页与账单检查Agent心跳、原实例/磁盘/网络、归属、已付到期、余额和库存；出现客观阻断时保留保护和下一次自动动作。面板备份不含客户VPS磁盘，也不会生成备份截止之后的交易。本版首装的本地OSS替身不代替真实新B灾备验收。

## 日志与完成判据

管理员在「日志」（`/admin/logs`）设置发生时间范围，分别按宿主名称、历史实例编号及描述搜索「开通失败」「清理」「回收」「转移」「重试」「IP」。对照失败→清理→新核验→恢复的时间顺序，记录目标、失败步骤、原因、已执行动作、下次自动动作和最终结果。旧一次“隔离已解除”不能证明后来没有再次失败；历史没有原始失败步骤时如实保留未知，不猜换IP或IPv6原因。

网页升级任务完成、实际版本/提交一致，七项页面反馈与专用测试流程通过，才记录该目标本版验收。自动恢复须同时有原身份/库存/残留核验及最终恢复结果；支付/转移须核订单和手续费次数；备份须核完整上传结果。发行CI成功不代替这些生产结果。

## 验证范围

本机验证使用隔离 PostgreSQL、受控mTLS Incus/Caddy边界、真实Vue/Chrome；发行双架构首装中的OSS是本地传输替身。真实OCI/原Agent与客户公网持续观察、真实OSS全新B完整灾备、独立备用接管、近千台和72小时仍需各自验收。网页升级成功也不代表这些目标全部完成。
