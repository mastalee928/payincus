# 客户网络防护与自动可售三轮复审（2026-11-11）

当前为 v1.8.6／Agent v1.0.6 发行准备，尚未发行或部署。本轮在前期非特权加固、一机一卖生命周期和纯净系统接入修复上继续检查。正式来源、终态运行与公开资产以 [发行记录](release-v1.8.6-validation.md)为准。

## 第一轮：客户与管理边界

- Agent 在宿主的独立 nft inet 表按受管客户桥入口实施隔离，不能靠客户改源 IP 或容器内规则解除。DNAT 前后均阻断 `169.254.0.0/16`，覆盖 OCI metadata 的全部端口与原已建立连接；不修改宿主 OUTPUT，Agent 的 OCI IPv6发现继续可用。
- 客户主动访问宿主服务、私网、管理隧道、已识别管理地址被隔离，保留 DNS、DHCP、必要 IPv6邻居发现和公开80／443门户。公网SSH验收仍走真实公网入口，仅对已识别管理来源的入站DNAT连接转换来源；普通客户连接保留原来源。
- 客户实例API的宿主字段改为显式白名单，原始管理资料不会随新增宿主字段透传。交付、SSH维护、原客户启动恢复及面板恢复验收前通过原受信Incus API读取宿主防护回执。
- 公开域名、用户原已知道的地址、第三方记录和未识别的其他出口不可能保证绝对隐藏。地址隔离不代替管理接口鉴权。未支持的外接桥／macvlan／routed／VLAN等拓扑不能冒充已防护。

## 第二轮：持久恢复与条件判断

- 每30秒核当前桥、管理地址、实际内核规则，原子重建独立表；既有管理地址保留，暂时DNS／Incus不可用时恢复已保存策略。磁盘／命令／回读失败撤销成功回执，不能凭命令退出或规则数量标绿。
- 实测发现 nft 事务echo可遗漏delete并重复输出table，且匿名集合回读顺序不同。仅规范化这些无序表现，保留同链规则和表达式顺序，逐项比较所有match／verdict／hook／NAT；真实 nft1.1.6序列化样本收入回归。
- 防护先于Incus启动，OpenRC／systemd均增加真实依赖。失败记录本次boot ID，规则恢复并回读后自动续接受阻且启用的服务；没有失败回执、旧boot回执或已完成回执不重新启动服务。运行中不重启Incus／客户。
- 原OCI防火墙可能拒绝宿主主动连接客机后的回包；固定安装脚本与Agent均只补 `ct direction REPLY` 规则，保留客户主动访问管理面的阻断，不清空其他规则。
- Agent既有心跳间隔超过60秒时收紧为60秒；库存上报窗口考虑30秒巡检、执行与传输延迟，交付时仍独立核宿主90秒有效回执。缺失、过期、失败和未来回执不售，条件恢复后自动入库。

## 第三轮：接入至可售与发行链路

- 复用当前权限／lease、固定SSH身份、已加密密码、原任务维护、当前boot及客户占用保护。纯净系统准备包括依赖、准确UTC、ipinfo有效IANA时区、chrony、内核支持时BBR、至少1GiB磁盘swap；原swap不缩小不关闭。
- 下载失败、包锁、资源暂时不足、管理暂断和防护等待按原因退避续接；已完成阶段按持久回执继续。未知安装中断不盲重装，身份变化／残留未清不能跳过。完整安全／Agent回执、无客户与无清理占用后，库存／目录／管理员库存／带锁分配器使用同一可售条件。
- 新Agent须先形成受验公开资产，面板沿已有受信自动升级链路交付。双架构CI新增实际网络包、原子规则恢复、systemd及Alpine OpenRC依赖恢复测试；预览、正式首装与公开资产独立核验。
