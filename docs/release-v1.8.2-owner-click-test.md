# v1.8.2 网页升级与检查

发行CI、双架构首装和六公开资产已核验，见[发行验证记录](release-v1.8.2-validation.md)与[v1.8.2 Release](https://github.com/mastalee928/payincus/releases/tag/v1.8.2)。本版保留v1.8.1支付和普通OSS自动还原，新增接入生命周期、OCI公网IP同步、来源IP和购买页修正。只读诊断确认目标主控已经v1.8.2；agent未代做升级。已升级目标直接做下述检查，无需重复更新。

已知限制：旧清理任务已完成后又发生开通失败，宿主可能再次隔离而没有自动重新核验，IPv4/IPv6因此等待。该遗漏在v1.8.2尚未修复，不能把“在线”或“地址已读取”当成恢复完成。

## 升级

1. 超级管理员打开「版本更新」（`/admin/system-update`），点击「检查更新」，确认目标为 **v1.8.2**。
2. 点击「更新到最新版本」，确认一次后等待后台备份、迁移和重启结束；重新进入确认当前版本为 **1.8.2**。
3. 正常升级不需要 OSS 还原。新包含两项新迁移，数据库迁移总数为240；不改客户磁盘、订单、价格或账期。

## 机器池与重装后接入

1. 进入「机器池→新增宿主」，输入已经接入且在线的宿主 IP。输入框直接提示已在机器池，并可定位原宿主；不会再次安装。
2. 对尚未成功建立正式 Host 的失败接入任务，重装后使用当前 root 密码点击普通重试。系统重新认证当前系统、确认没有客户实例，随后清理旧登记并继续接入，不要求填写旧 SSH 指纹。
3. 从机器池删除无客户、无在途任务的宿主后，可用重装后的机器重新接入。清理尚未结束时可在「接入任务」查看自动续接进度。已有客户的宿主继续拒绝不安全删除。
4. 隐藏接入任务历史不会删除仍在机器池的宿主管理通道；不要把隐藏历史当成删除宿主。

## OCI 更换公网 IP

1. 在 OCI 删除原公网 IP 并向同一宿主附加新公网 IP；保留原系统、主私网地址和实例。删除与附加之间公网连接会短暂中断。
2. 管理后台机器池、节点列表/详情与用户机器列表/网络页自动更新当前 IP。用户端仅显示地址，不增加确认步骤。
3. 平台按原 WireGuard/Incus/Agent 身份重连，并核验新入口的 SSH 身份。临时断网自动退避，恢复后清除等待状态；原密钥、实例、磁盘和计费保持。
4. A 原来使用 `1.1.1.1`，核验换为 `1.1.1.2` 后，B 可以使用回收的 `1.1.1.1`。B 按 B 的身份核验，A 的历史 IP 不成为 B 的身份，也不会阻挡已释放的地址。地址仍被另一台当前宿主占用时保留保护，等待其安全更新后续接。
5. 关机实例仍保持关机，新观察地址可以显示，开机后自动续接公网核验；平台不会为了检查 IP 强制开机。真实身份不符或未消除的地址占用不会伪装成功。
6. 宿主出现“原故障隔离保留”或IPv6提示“机器处于故障隔离”时，到机器池恢复检查查看客户占用、残留、身份与自动恢复进度；不要连续点击“立即同步IPv6”。若实际检查通过但旧任务done且仍隔离，属于上方已知遗漏，保存宿主编号、检测时间和日志供修复，不删除客户或重建密钥。

客户电脑若记住该 IP 上另一台机器的 SSH key，SSH 客户端可能提示变化。确认新地址与机器归属后，在客户电脑处理该地址的旧缓存；平台不能修改客户电脑或无条件接受未知密钥。

## 购买页、主题与来源 IP

1. 打开 `/purchase`，切换洲和地区：旧配置、系统镜像、数量及金额立即失效，不出现旧配置残影；重新选择当前地区商品。
2. 配置卡片 CPU/内存/磁盘横排且各列居中，库存显示 `库存:N`。检查手机与桌面、深色与浅色。
3. 首页主题按钮与全站一致，可选跟随系统、亮色、暗色；跟随系统时系统设置变化立即生效。
4. 用户重新登录后，在「用户→用户活动」检查新登录来源。双层本机代理不再将外部地址记录为127.0.0.1；历史记录保持原样。外部独立代理使用已登记IP/CIDR信任配置。

## 保留的支付与 OSS 还原流程

1. 用专用测试账户在`/purchase`选一台可售机器，直接购买应进入独立确认页；另一份选择加入购物车，购物车支持批量结算。核地区/配置/数量/金额一致。
2. 余额付款一次确认后核订单、余额流水与实际交付；第三方用已配置通道付款，核到账后自动交付、购买款不先进余额、不要求二次确认。切换支付宝、微信或USDT后核通道/金额，清空购物车不会强制旧未付单。
3. 在管理员订单/账单和专用账户实例页对照订单与实例、扣款或退款、账期和状态。重复回执防重与失败退款已有隔离验证；真实通道重复回调只在授权测试通道执行。

在管理员「阿里云OSS」先核保存的配置与最近完整备份状态，创建备份后等待上传和完整性结果成功，再下载或用于预检；不要以“已开始”当成可恢复备份。普通升级无需点击还原。

异机还原保持原正式域名。原主控失联后，owner 先把域名指向新 B，再登录 B 保存 OSS 资料、选择完整备份并点击还原。后台自动预检、恢复原数据/身份、观察宿主与 Agent 重连并恢复业务；不逐台填写技术参数或补交账目。新包保留宿主删除的持久回执，并在仅隐藏任务时保留现用宿主原管理路由。恢复到所选备份时点，不生成未备份交易或客户磁盘。

## 日志和验证范围

管理员在「日志」按宿主编号/名称及时间查接入清理、IP 更新、自动重试与最终结果。机器池接入任务保留未完成清理，公网 IP 管理弹窗显示实际错误及下一次检查。真实身份变化不静默重建密钥。

查故障时同时按历史实例编号搜索，失败开通日志可能不含宿主名称。先对照开通失败→清理→恢复的时间；旧“隔离已解除”不能证明之后没有再次失败。没有具体失败步骤记录时如实保留未知原因。

本轮已完成源码与隔离PostgreSQL、不同真实SSH key握手、加密备份还原、Vue浏览器及发行CI/双架构首装核验。Owner确认另一生产宿主换IP成功，受隔离宿主未换IP；单台成功不能替代全部边界验收。独立真实OSS新B、原Agent/客户公网持续观察、近千台及72小时尚未全面验收，已知隔离遗漏也尚未修复。
