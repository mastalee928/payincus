# Alpine SSH 密码认证安全修复

采用 Alpine 当前分支的官方签名 OpenSSH 安全修订，保留用户原密码、主机密钥、端口和 SSH 配置，不关闭密码认证，不强制切换 PAM。依据 [OpenSSH 10.6p2 公告](https://www.openssh.com/releasenotes.html)和 Alpine stable 分支的 `main/openssh/pw.patch`；不能只看 SSH banner 判断是否已修补。

本轮是源码修复和隔离验证，生产宿主及客户实例未执行更新。修复已推至 [codex/alpine-ssh-security 分支](https://github.com/mastalee928/payincus/tree/codex/alpine-ssh-security)，未合并 main 或发布新安装包；现有 v1.8.3 包不包含本轮改动。部署修复源码后的面板不会自行扫描或改动客户系统。

## 新安装

Alpine 容器和 VM 的初始化先安装并检查官方补丁；检查缺失或失败不能通过独占公网 SSH 交付核验。Alpine 宿主接入安装脚本在既有管理通道建立后使用同一补丁检查。其他系统不执行 Alpine 包更新。

## 已交付实例：管理员网页维护

1. 管理端打开「实例」→目标实例详情。目标须为已交付、运行中的独占实例。
2. 点击「SSH 安全维护」。无需输入客户密码或 SSH 地址，后台沿原受信管理连接、原实例 UUID 与已保存的客户密码执行。客户已自行改密码且与面板记录不一致时，原密码预检失败，更新不会开始；本入口不重置客户密码。
3. 后台先验证原密码连接，安装同版本官方安全修订，核运行中的 SSH 已加载补丁，比较 SSH 配置/密钥/账户文件及权限。随后验证原连接仍可执行、新连接仍能使用原密码，全部通过才记录成功。
4. 管理员「日志」可查看 `SSH 安全维护`结果。转移/恢复/快照/反代/实例任务冲突、管理员会话失效或原身份不符时，不更新客户系统。

维护要求原登记 `managedCleanup` 的 attempt、endpointHash 和 UUID 均与当前受信 Incus 一致。旧实例缺此登记、恢复后只有 `recoveryIdentity`，或换机后仍留旧登记时会拒绝；此项不等于客户系统故障。保留原身份和错误记录，按原恢复/换机协议核对，不能直接补随机 UUID 或删检查。当前入口只支持已交付的运行独占实例，停止/未就绪实例不执行维护。

客户继续使用原 IP、端口和密码，无需更改设置。此维护不重启实例；只在运行的监听进程仍为旧二进制时 reload SSH。验证连接保持只能证明该次连接；全体线上连接的零中断须在授权生产维护中另行记录。

官方补丁下载、安装或重载未完成会返回失败，不恢复到有漏洞的旧包。再次执行时重新核原身份、权限、冲突、包和运行中监听进程；包已更新但 reload 失败不会被误报为已完成。异常中断留下的本机互斥目录或自定义 SSH PID/二进制配置会阻止维护，需要运维核实原进程后处理，不能绕过门禁。

当前安全基线如下。使用该分支 main 的 HTTPS 仓库和原 APK 信任密钥，保持客户原 repositories；同步已安装的 PAM/Krb/SFTP/client 变体，不更换原认证方式。

|---|---|---|---|
| 3.19 | `9.6_p1-r3` | r2 → r3 | AMD64 |
| 3.20 | `9.7_p1-r6` | r5 → r6 | AMD64 |

维护仅接受对应上游版本的同分支修订；会触发官方自动 restart 钩子的旧修订（例如3.22早于 `10.0_p1-r2`）、跨版本升级、不在基线中的分支及自定义服务参数均拒绝自动更新。上述最新修订升级通过，不代表每个更旧修订的钩子已逐一运行验收。不得通过混用 edge、关闭 APK 验签、替换密码或更改客户 SSH 配置绕过。

本机相关类型、server build、双前端 build、Alpine/宿主安装/前端路由/i18n 守卫通过。Chrome 真实管理员详情页核三宽1440/768/390、三语/深浅、44px按钮、无溢出、重复点击和旧会话迟到结果。18 OS alias × 容器/VM生成及真实本机 SSH 登录专项保留原非Alpine行为。日志与图片只存本地 ignored logs，公开台账不含客户凭据。
