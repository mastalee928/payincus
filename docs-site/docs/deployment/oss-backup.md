# 阿里云 OSS 平台备份

管理员后台「系统」分组的 OAuth 下方提供「阿里云OSS」。平台备份包含完整数据库、机器池分组和已接入宿主的登记信息、运行环境、受管证书，以及本机管理网关的 WireGuard/SSH 身份与节点地址登记。

客户 VPS 磁盘、远端独立网关文件、外部图床及邮箱原件需另行保护。换 IP 后的 WireGuard 自动重连不在当前范围内。

## 安装要求

要求标准 `/opt/incudal` Linux/systemd 部署、本机 PostgreSQL、非超级用户的应用数据库角色及同大版本 `pg_dump`/`pg_restore`。恢复另需本机 postgres peer 管理通道。私有后端仍只能运行一个实例。

标准安装和更新会自动配置备份组件；后端启动前也会运行安装检查，补齐状态目录、systemd 服务与受限调用权限。仅手动替换旧平铺部署中的应用文件时，旧服务配置可能尚未包含启动检查；本次热更新需要同时应用新版服务配置。若仍提示组件未就绪，先检查部署日志；维护者可在经授权的维护窗口、确认运行的是已验证发行源码后执行修复：

```bash
# 原子布局
sudo bash /opt/incudal/current/scripts/install-platform-backup.sh

# 旧平铺布局使用 /opt/incudal/scripts/install-platform-backup.sh
```

脚本安装 `incudal-platform-backup@.service`、受限 sudo wrapper、状态目录和后端 drop-in；不会额外启动 API 实例。备份和 systemd OTA 共用维护锁，不能同时执行。不要绕过帮助程序并行维护数据库、轮换密钥或替换受管文件。

## 配置与备份

1. 先填写 AccessKey ID 与 AccessKey Secret，点击连接区的「保存设置」。此时无需选桶或填写备份密码；已有秘密字段留空表示保持。
2. 浏览或新建私有 Standard 桶，选择区域、桶和备份目录。当前严格保留策略拒绝启用/曾启用版本控制、WORM 或启用生命周期规则的桶。
3. 「保存并测试连接」先保存当前信息，再测试。未选桶时验证列桶权限；选桶后验证桶条件，并执行探测对象写入、读取和删除。填写独立备份密码、保存并测试成功后，才可开启自动备份或立即备份。
4. 上传周期可选 1/3/6/12/24/72 小时，保留最新 1/3/5 份。新包回读校验后才标记完成并清理旧备份。

默认仅用户名为 `admin` 的管理员可管理备份。需授权其他管理员时，由维护者设置 `PLATFORM_BACKUP_ALLOWED_ADMIN_IDS` 为明确的正整数 ID 列表。演示环境不开放备份管理。

最小 RAM 权限按能力拆分：列桶、新建/删除桶、桶地域/ACL/版本控制/WORM/生命周期读取，以及专用前缀内对象读写、删除、分片上传和清理。没有列桶权限时可手动填写已授权桶名。应在专用测试桶核验实际权限，不要求默认授予整个账号 OSS 全权限。

密码须另行安全保存，旧包仍需要其原密码。当前包采用 scrypt 与 AES-256-GCM，单包上限 32 GiB；只有完整认证通过才会提取。平台运行配置中的秘密也加密保存，网页不回传秘密原文或密文。

### 完整性与可恢复性

每份新备份对整个应用数据库执行导出，不按业务类型或表筛选。完整恢复文件保留对象归属、授权和大对象；数据库角色、授权及表空间资料另存为加密包内的 `database-globals.sql`，数据库属性和完整性报告存为 `database-integrity.json`。

导出与逐表校验使用同一个 PostgreSQL 事务快照。系统对每张表的完整行内容计算校验指纹，覆盖重复行和没有主键的表，并记录行数；大对象内容另行校验。序列计数器不受 MVCC 快照控制，因此从整库导出文件记录其确切值，并在还原后核对。上传前在 UUID 命名的临时数据库中实际还原，核对表清单、结构、行数、内容指纹、序列和大对象。校验失败不会发布完成标记，也不会清理旧备份。恢复预检与正式恢复也会复核新包中的报告，正式恢复的复核位于会话失效等安全处理之前。

行内容使用 PostgreSQL 原始记录表示计算 SHA256，保留数组下标、空值、JSON 原文和数值精度等细节；不经过 JavaScript 数值转换或 JSON 简化。校验查询固定使用系统函数搜索路径，避免同名业务函数影响结果。

这需要额外的本机数据库空间、读取和排序资源。外部表、只读备库、当前未支持的 ICU 数据库区域设置或其他无法完整验证的情况会拒绝备份；不能把错误当作成功或静默跳过表。归档大小和文件清单上限超出时同样失败，不截断数据。

归属及授权资料完整留在加密包中；隔离验证库使用目标应用角色映射。系统不会自动执行归档中的全局角色 SQL，避免将原服务器的超级用户和权限直接导入目标集群。实际换机时需核对并映射这些资料。旧包不含新增完整性报告，不能被追认成已通过逐表验证的新备份。

每份备份覆盖所记录快照时刻已提交的全库数据。两次备份之间新增交易的灾难恢复需另配持续 WAL 归档，本功能不将定时快照等同于零数据丢失。

### ZIP 封装与加密

完整性验证通过后，整库恢复文件、权限资料、校验报告、平台配置和文件清单按名称整理到标准 ZIP/ZIP64 包，再用备份密码整体加密为 `payload.enc` 上传。数据库恢复文件已经由 PostgreSQL 压缩，ZIP 中保留原字节，避免重复压缩。解密认证通过后保留标准 `database-backup.zip`，可用常见 ZIP 工具查看内部文件；SQL 表结构和数据仍以完整的 `database.dump` 为权威恢复来源。

新包使用 `PICBKP02` 加密头；新代码继续读取旧 `PICBKP01` 包。旧发行包不支持新 ZIP 加密头，恢复新包必须使用包含本次实现的程序。认证、路径、重复条目、声明大小、解压大小、文件清单和 SHA256 均检查通过后才允许使用内部内容，不自动执行 ZIP 中的全局权限 SQL。

## 从备份恢复

管理端 OSS 页面底部提供「恢复指南与工具」，可直接查看中文步骤并下载说明与交互工具。每个新备份集在保留 `payload.enc` 和 `complete.json` 的同时，额外上传 `payincus-backup-YYYYMMDD-HHMMSS-UTC.zip`，与自动恢复备份使用同一个密码。UTC 比北京时间早 8 小时。可用支持 AES-256 ZIP/ZIP64 的 7-Zip 或 WinRAR 浏览；文件名可见，内容需要密码。

额外 ZIP 保存 `manifest.json`（快照时间、版本及校验信息）、整库 `database.dump`、整库 `database.sql`、按名称排列的 `tables/<schema>/<table>.sql`、角色/授权、校验报告、运行配置、受管身份资料、中文说明和恢复工具。SQL 从已验证的同一个整库归档生成；不能将逐表 SQL 零散导入运营库。正式面板恢复继续读取原 `payload.enc`。新备份需通过整库恢复校验、ZIP 每项解密哈希校验及两份对象的 OSS 回读，才写入完成标记并清理旧备份。旧备份不会自动补生成 ZIP。

命令行交互工具可在匹配版本的目标主控执行 `sudo python3 payincus-recovery.py`，选择 configure、preview、status、restore、rollback 或 resume。密码通过交互输入，不进入命令参数。工具调用目标机已安装的恢复执行器，不执行归档中的代码。

1. 隔离旧主控，准备相同应用版本、迁移历史、PostgreSQL 大版本的目标安装。数据库损坏时先保留原数据，再准备可用的同版本目标库；本功能不修复数据库集群。
2. 新机配置可访问原桶的凭据，填写原安装前缀查找备份。系统不会自动接管原安装的备份清理命名空间。
3. 输入原密码执行恢复预检，下载认证后在隔离数据库实际还原。预检有效期 15 分钟，绑定发起管理员。
4. 输入页面显示的 `RESTORE <预检ID>` 确认。系统设置数据库外的持久化恢复保护，停止后端，切换数据库和受管文件，再启动受保护的唯一后端。
5. 保护期内业务、Agent、回调、WebSocket 和后台业务任务暂停；旧会话/API 凭据失效，待处理任务和机器池库存需核对。管理员密码登录及必要验证码配置仍可用。
6. 核对真实支付、宿主、实例、库存、权限与任务后，输入 `RESUME AFTER RECONCILIATION` 恢复运营。需要回退时，在保护仍有效期间使用 `ROLLBACK RESTORE`；回退后仍保持保护。

恢复保护期间，普通业务查询暂停，用户、机器池和版本页面不可用于判断数据是否丢失。恢复核对完成并解除保护后，这些页面恢复查询。机器池的库存隔离不会自动清除：在「机器池」勾选隔离宿主，使用「检查并恢复所选宿主」，或点击「批量检查本页隔离宿主」。弹窗逐台显示检查与恢复结果，仅允许恢复检查通过的项。空闲宿主核对为空后解除隔离；已有用户实例时，核对实例归属、运行状态、存储及 IPv4/IPv6 转发一致后，保留实例、价格、到期时间、账务和资源占用，只解除隔离，仍显示已分配，不会重复出售。待清理账务、离线、实例不匹配、未知系统或额外数据卷时继续隔离。遗留系统清理仍须确认，不会批量删除未知或运行中的实例。

同一主控的 WireGuard 配置未变化时，恢复及回退保持现有管理接口运行；配置需要更新时同步保留同一控制身份下的已知节点端点。已经失联且主控没有端点的宿主仍需在云厂商串口控制台重新加载其已有隧道配置。公网 22 已交给客户实例时，不应尝试通过该端口登录宿主。维护者可在实际宿主 root 控制台运行仓库中的 `scripts/reconnect-host-management.sh`；该工具保留密钥、磁盘、实例和端口分配，只重新加载现有隧道并重启监控 Agent。

管理员宿主列表、详情与机器池按最新心跳显示在线或离线。客户概览、实例列表和详情在连接不可用时显示「故障」，不暴露内部架构原因，也不把历史运行状态当作实时状态。该显示标记不改动数据库中的实例状态、归属或账务；连接恢复后自动采用正常显示。

恢复 `.env` 时自动合并原 `ENCRYPTION_KEY`，保留目标机数据库连接、JWT 身份和运行控制。其余原配置保存在私有归档中供人工映射。换 IP 时须核对域名、第三方回调/白名单、网关指纹及节点 Endpoint，不能假定恢复数据库便会自动连通宿主。

恢复与回退均关闭备份调度并清除测试状态，需重新测试后显式开启。回退数据库与私有证据不自动删除，由维护者验收后决定清理；不要直接删保护标记。

## 后台无法登录时

root 可使用命令行入口，参数不携带凭据。例如原子布局读取任务状态：

```bash
sudo env NODE_ENV=production ENV_FILE=/opt/incudal/.env \
  /usr/bin/node /opt/incudal/current/server/dist/scripts/platform-backup-cli.js status
```

平铺布局去掉路径中的 `current/`。其他命令从标准输入读取 JSON，秘密使用 root 0600 的本地输入文件，不写到 shell 历史、工单或聊天中。

| 命令 | 输入字段 |
| --- | --- |
| `configure` | region、bucket、prefix、accessKeyId、accessKeySecret、backupPassword、intervalHours、retention；保存后保持调度关闭 |
| `backup` | 无 |
| `preview` | prefix、password |
| `restore` | previewId、confirmation（`RESTORE <previewId>`） |
| `rollback` | confirmation（`ROLLBACK RESTORE`） |
| `resume` | confirmation（`RESUME AFTER RECONCILIATION`） |

CLI 预检只能由 CLI 确认恢复。状态目录为 `/var/lib/incudal-backup`，其中 `private` 仅 root 可读，包含明文恢复暂存、回退文件及 journal，禁止公开。

## 验证范围

本地测试覆盖配置、加密、错误密码、篡改、文件边界、保留策略和已安装 SDK 的真实上传代码路径；HTTP 边界使用替身。发布 CI 在一次性 Linux 主控上检查数据库、systemd、恢复保护、回退及主密钥一致性，OSS 存储使用本地文件替身。

**真实阿里云 OSS RAM 权限、上传与云端故障清理仍需专用测试桶验收。** 首次正式启用前应完成真实备份和恢复演练，不能把 CI、本地测试或 GitHub 发版等同于生产主控已验证。
